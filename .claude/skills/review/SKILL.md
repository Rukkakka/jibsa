`docs/development/agents.md` 의 "코드 리뷰" 절을 실행한다. 대상: `$ARGUMENTS` (비어 있으면 커밋 전 변경과 이 브랜치의 커밋 전부: `git diff HEAD`, `git status --short` 의 추적 안 된 파일, `git diff main...HEAD`. 에이전트는 시키지 않으면 커밋하지 않아 리뷰할 변경이 대개 커밋 전에 있다).

1. **지적 모으기.** 다음 관점마다 리뷰어를 띄우거나(`general-purpose`, Sonnet high. 얽힌 변경이면 Opus high, 여러 명령에 번지는 큰 변경이면 Opus xhigh) `/code-review` 를 돌려 지적을 모은다. 리뷰어는 코드만 읽고 수정하지 않는다.
   - 규약 위반: `AGENTS.md` "꼭 지킬 것" (로그인 없는 기능만, 만원, stdout·stderr JSON, 만료 제외, 서버가 거른 결과 다시 거르지 않기, 소스끼리 import 금지, 브라우저 transport·요청 제한 훅, 사진·연락처·본문·좌표 출력 금지).
   - 정확성·버그: 잘못된 분기, 누락값 규칙(해당 없음은 키 삭제·모름은 null·비어 있음은 `[]`), 단위 환산.
   - 출력 계약: `docs/development/output-contract.md` 와 `docs/<source>.md` 의 필드·에러 코드와 일치하는지.
   - 웹 대응: `docs/development/provider-conventions.md` "웹 화면과의 대응" 기준으로 웹에 없는 결과를 만드는지, 다르게 한 곳이 "웹과 다른 점" 에 적혔는지.
   - 요청 수·차단 위험: 매물마다 추가 조회처럼 요청을 늘리는 변경, 요청 제한 훅을 거치지 않는 요청.
2. **지적 재검증.** 모은 지적을 중복 제거해 `review-verifier` 에이전트(읽기 전용)에 넘긴다. 지적이 많으면 소스별로 나누되 실제 API 를 부르는 에이전트는 소스당 하나만 띄운다.
3. **가르기와 보고.** 검증 결과를 받아 진짜 문제와 오탐만 사용자에게 보고한다 (근거: 재현 명령·응답 핵심 필드·`파일:줄`). 일어날 수 없는 지적은 뺀다. 오탐은 어디에 어떤 문장으로 남길지(코드 주석 `# 리뷰 오탐 (YYYY-MM-DD): 이유` 또는 소스 가이드 "웹과 다른 점")를 함께 제안한다.
4. 고치는 것과 오탐 기록 남기기는 **사용자가 정한 뒤** 한다. 커밋·PR 코멘트는 시킬 때만.
