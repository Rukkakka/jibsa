# 직방 CLI 사용법 (`jibsa zigbang`)

[설치](../README.md) · [공통 사용 규칙](common.md) · [개발 가이드](../references/providers/zigbang.md)

> 금액은 **만원**, 면적은 **㎡**다. `search listings stay`는 월세 대신 **주당 요금**을 쓴다. 출력 형식·누락값·에러 대응·요청 제한 같은 공통 규칙은 [공통 사용 규칙](common.md)에 있고, 이 문서는 직방에만 있는 내용을 적는다.

## 한눈에 보기

| 명령 | 하는 일 | 무엇을 넣나 | 다음에 쓰는 곳 |
| --- | --- | --- | --- |
| `search locations` | 지역·단지 후보 찾기 | 지역·역·학교·단지 이름 | `search listings`, `complex`, `search listings --complex` |
| `search listings room` | 원룸·빌라·오피스텔 매물 찾기 | 지역 또는 좌표 | `listing` |
| `search listings apt` | 아파트 매물 찾기 | 동·구·역 또는 좌표 | `complex`, `search listings --complex`, `listing` |
| `search listings store` | 상가·사무실 매물 찾기 | 지역 또는 좌표 | `listing` |
| `search listings stay` | 주 단위 단기임대 찾기 | 지역 또는 좌표 | `listing` |
| `complex` | 아파트 단지·오피스텔 건물 정보 | 단지 ID | `search listings --complex`, `real-price`(아파트) |
| `search listings --complex` | 단지·건물 안 매물 목록 | 단지 ID | `listing` |
| `real-price` | 아파트 실거래가 | 아파트 단지 ID | — |
| `listing` | 매물 하나 상세 | 매물 ID | — |

### 보통 이렇게 이어서 쓴다

```text
지역에서 집 찾기   search listings room / apt / store / stay → listing
단지 골라 집 찾기  search locations → complex → search listings --complex → listing
                            └→ real-price (아파트)
```

## 옵션 읽는 법

각 표는 현재 CLI의 인자·옵션·기본값을 기준으로 한다. `미지정`은 별도의 필터를 적용하지 않는다는 뜻이다. 범위는 양 끝을 포함하며 개별 예외는 설명에 적었다. 목록형 옵션은 도움말에 표시된 대로 반복하거나 쉼표로 지정한다.

```bash
jibsa zigbang search listings room 역삼동 -t 빌라,오피스텔 --trade 전세
jibsa zigbang search listings room 신림역 --option 에어컨 --option 세탁기
```

좌표는 `--lat`·`--lng`를 함께 주고 대한민국 좌표를 사용한다. 이름 대신 좌표를 주면 지역 인자는 생략할 수 있다. 금액·면적 하한과 상한을 함께 주면 하한은 상한 이하여야 한다.

## 1. `search locations` — 지역·단지 후보 찾기

지역과 단지·오피스텔 후보를 찾아 후속 조회의 ID를 고른다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `QUERY` | 지역·역·학교·단지 이름 (예: 역삼동, 강남역, 디에이치퍼스티어아이파크) | 필수 |
| `--limit` | 지역·단지 후보 각각의 최대 결과 수 범위: 1~1200. | 120 |

**사용 예시**

```bash
jibsa zigbang search locations 디에이치퍼스티어아이파크
```

**반환값**

`results`(지역 후보), `complexes`(단지 후보)를 준다.

**오류와 대응**

검색어 누락·한도 범위 위반은 `INVALID_ARGUMENT`.

**주의사항**

`results[]`는 지역 후보, `complexes[]`는 아파트·오피스텔 후보다. `complexes[].complex_id`를 `complex`·`search listings --complex`에 넘긴다. 이름·별칭이 비슷한 다른 단지가 섞일 수 있으므로 주소·세대수로 고른다. `--limit`은 두 후보 목록에 각각 적용한다.

## 2. `search listings room` — 원룸·빌라·오피스텔 매물 찾기

원룸·빌라·오피스텔 매물을 지역·역·좌표로 찾는다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `QUERY` | 검색 중심 지역·역 이름 (예: 역삼동, 강남역). --lat/--lng 를 주면 생략 | 미지정 |
| `--lat` | 중심 위도 (query 대신) | 미지정 |
| `--lng` | 중심 경도 (query 대신) | 미지정 |
| `--type` / `-t` | 매물 유형: 원룸, 오피스텔, 빌라. 반복하거나 쉼표로 구분. 기본 전체. 원룸은 방 하나짜리라 원룸형 오피스텔도 나온다 (방 1개짜리 아파트는 search listings apt 로) | 미지정 |
| `--trade` | 거래 유형: 전세, 월세, 매매, 단기임대. 반복하거나 쉼표로 구분. 기본 전체 (월세에는 단기임대가 빠진다) | 미지정 |
| `--room` | 방 구조: 오픈형원룸, 분리형원룸, 복층형원룸, 투룸, 쓰리룸, 포룸이상. 반복하거나 쉼표로 구분 (OR). 원룸 카테고리=원룸형 3종(빌라 건물 원룸 포함), 빌라=투룸 이상, 오피스텔=원룸형·투룸·쓰리룸 이상 | 미지정 |
| `--radius` | 검색 반경 (km, 기본 1). 동 이름에 --radius 를 주지 않으면 반경 대신 그 동 경계 안을 찾는다. 반경 안 매물이 모자라면 반경 밖 가까운 매물도 나온다 범위: 0.1~5.0. | 미지정 |
| `--limit` | 확인할 가까운 매물 수 (제외 전) 범위: 1~120. | 15 |
| `--deposit-min` | 보증금/전세금 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--deposit-max` | 보증금/전세금 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--rent-min` | 월세 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--rent-max` | 월세 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--price-min` | 매매가 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--price-max` | 매매가 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--manage-cost-min` | 월 관리비 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--manage-cost-max` | 월 관리비 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--no-manage-cost` | 관리비 없는 매물만 (관리비 범위와 함께 못 씀) | 꺼짐 |
| `--area-min` | 면적 하한 (㎡) 범위: 0~제한 없음. | 미지정 |
| `--area-max` | 면적 상한 (㎡) 범위: 0~제한 없음. | 미지정 |
| `--area-pyeong-min` | 면적 하한 (평). ㎡ 조건과 함께 주면 둘 다 만족 범위: 0~제한 없음. | 미지정 |
| `--area-pyeong-max` | 면적 상한 (평) 범위: 0~제한 없음. | 미지정 |
| `--floor` | 층: 지상, 반지하, 옥탑방, 1층. 반복하거나 쉼표로 구분 (OR). 지상은 반지하·옥탑방 제외 | 미지정 |
| `--bathroom` | 욕실 수. 1·2 는 정확히 그 수, 3 은 3개 이상 범위: 1~3. | 미지정 |
| `--option` | 옵션: 에어컨, 냉장고, 세탁기, 가스레인지, 인덕션, 전자레인지, 책상, 책장, 침대, 옷장, 신발장, 싱크대. 반복하거나 쉼표로 구분 (AND, 모두 갖춘 매물) | 미지정 |
| `--condition` | 기타 조건: 즉시입주, 남향, 엘리베이터, 주차, CCTV, 반려동물, 전세대출, 전기차충전. 반복하거나 쉼표로 구분 (AND) | 미지정 |
| `--without-random` | 오피스텔 서버의 무작위 섞기 해제. 검색 결과는 거리순 유지 | 꺼짐 |

**사용 예시**

```bash
jibsa zigbang search listings room 역삼동 -t 원룸 --trade 월세 --deposit-max 1000 --rent-max 70
```

**반환값**

`region`, `boundary` 또는 `radius_km`, `total_in_radius`, `returned`, `listings`를 준다.

**오류와 대응**

옵션 충돌·범위 위반·지원하지 않는 유형/거래 조합은 `INVALID_ARGUMENT`. 지역 미발견은 `REGION_NOT_FOUND`. 직방은 행정동(`역삼1동`)을 모르므로 행정동 이름이면 힌트에 법정동 이름(`역삼동`)을 알려 준다.

**주의사항**

동 이름에 `--radius`·좌표를 주지 않으면 반경 원 대신 직방이 주는 그 동의 경계선 안 매물만 찾는다 (경계 요청 1회 추가). 옆 동 매물이 섞이거나 동 가장자리 매물이 빠지지 않는다. 결과에 `radius_km` 대신 `boundary`(동 이름)가 있고 `total_in_radius` 는 경계 안 수다. 구·시 이름은 너무 넓어 중심 반경으로 찾고 좁히라고 안내한다. 큰 읍·면처럼 경계가 반경 5km 원보다 넓으면(홍천 내면 등) 경계 대신 중심 반경으로 찾고 `notes` 로 알린다 (요청이 수백 번 나가지 않도록).

같은 이름의 동 없이 `○동N가` 로만 나뉜 동(성수동 → 성수동1가·성수동2가, 문래동 → 1가~6가)은 그 동들의 경계를 합쳐 모두 찾는다 (동마다 경계 요청 1회 추가). `boundary` 와 `region.name`·`region.address` 의 동은 `"성수동1가·성수동2가"` 처럼 합친 동 이름이고, 가까운 순은 합친 범위의 가운데에서 잰다. 같은 이름의 동도 따로 있으면(당산동과 당산동1가~6가) 그 동만 찾고 빠진 `○가` 동을 `notes` 로 알린다. `--radius` 를 주면 첫 `○가` 동을 중심으로 찾고 그렇다고 알린다.

역·학교·구·시·좌표는 반경 검색이며 기본 1km다. 일반 반경 검색은 부족하면 반경 밖 가까운 매물도 포함할 수 있고 `notes`로 알린다. 역 이름을 주면(직방 검색 결과가 지하철역) 역 전용 API로 그 역 반경 안 매물만 찾고, 반경 밖 매물을 이어 보여 주지 않는다.

원룸은 건물 종류가 아니라 방 하나짜리를 뜻한다. 직방 원룸 목록은 오피스텔을 섞어 주므로 오픈형·분리형·복층형 구조만 요청하고, 원룸형 오피스텔은 `property_type: "오피스텔"` 로 함께 나온다. `-t 원룸 --room 투룸` 처럼 원룸에 투룸 이상만 주면 원룸 쪽은 조회하지 않고 `notes` 로 알린다. 빌라 건물(다세대·다가구)의 원룸도 직방은 원룸 목록에 두고 빌라 목록에는 투룸 이상만 있어, `-t 빌라 --room 분리형원룸` 처럼 빌라에 원룸형 구조만 주면 빌라 쪽은 조회하지 않고 `-t 원룸` 을 쓰라고 `notes` 로 알린다. 방 1개짜리 아파트는 직방 아파트 목록에만 있고 방 구조 조건이 없어 원룸 검색에 나오지 않는다. `-t 원룸` 으로 찾으면 `search listings apt <동·구 이름> --supply-area-max 50` 으로 찾고 상세의 `room_count` 로 방 개수를 확인하라고 `notes` 로 알린다 (단기임대만 찾을 때는 빼고). 역·반경 아파트 검색은 면적을 받은 뒤 걸러 작은 아파트가 빠지기 쉬우니 동·구 이름으로 찾는다. 가까운 매물 `--limit` 건의 요약을 받아 거래 불가·조건 불일치로 뺀 만큼은 다시 조회하지 않고 `notes` 로 알린다.

`--floor`·`--room`의 여러 값은 OR, `--option`·`--condition`은 AND다. `--no-manage-cost`는 관리비 범위와 함께 사용할 수 없다. `--without-random`은 오피스텔을 포함할 때만 지원한다 (오피스텔 요청에만 적용하고 최종 결과는 거리순). 지원하지 않는 거래 유형 조합은 건너뛰고 안내할 수 있다.

직방은 단기임대를 원래 월세로 표시하지만 jibsa 는 `trade_type: "단기임대"` 로 구분한다. 역 근처 원룸은 절반 가까이가 단기임대라 `--trade` 없이 찾으면 많이 섞여 나온다. 이 단기임대(`--trade 단기임대`)는 중개사가 올린 원룸·빌라 매물이고, 주 단위 [`search listings stay`](#5-search-listings-stay--주-단위-단기임대-찾기)와는 다른 매물 서비스다.

결과의 `listings[].id`를 `listing`에 넘긴다. 오피스텔 매물의 `complex_id`는 건물의 `complex`·`search listings --complex` 조회에 사용할 수 있다. `-t 원룸` 만으로 찾아 섞여 나온 오피스텔도 건물 ID 를 채우며 (오피스텔 목록 요청이 추가된다), 그래도 못 찾으면 `null` 이다.

## 3. `search listings apt` — 아파트 매물 찾기

동·구 전체 또는 위치 반경의 아파트 매물을 찾는다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `QUERY` | 동·구 이름 (예: 역삼동, 강남구) 또는 역 이름 (예: 강남역). --lat/--lng 를 주면 생략 | 미지정 |
| `--lat` | 중심 위도 (query 대신) | 미지정 |
| `--lng` | 중심 경도 (query 대신) | 미지정 |
| `--radius` | 반경 (km, 최대 2). 주면 동·구 전체 대신 반경 안 단지를 가까운 순으로 훑는다. 역 이름·좌표면 기본 1km 범위: 0.1~2.0. | 미지정 |
| `--trade` | 거래 유형: 매매, 전세, 월세. 반복하거나 쉼표로 구분. 기본 전체 | 미지정 |
| `--limit` | 조회할 매물 수(제외 전), 범위: 1~120. | 20 |
| `--deposit-min` | 보증금/전세금 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--deposit-max` | 보증금/전세금 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--rent-min` | 월세 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--rent-max` | 월세 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--price-min` | 매매가 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--price-max` | 매매가 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--area-min` | 전용면적 하한 (㎡). 직방이 받지 않아 받은 뒤 거른다 범위: 0~제한 없음. | 미지정 |
| `--area-max` | 전용면적 상한 (㎡). 직방이 받지 않아 받은 뒤 거른다 범위: 0~제한 없음. | 미지정 |
| `--supply-area-min` | 공급면적 하한 (㎡). 동·구는 서버에서, 반경 검색은 받은 뒤 거른다 범위: 0~제한 없음. | 미지정 |
| `--supply-area-max` | 공급면적 상한 (㎡). 동·구는 서버에서, 반경 검색은 받은 뒤 거른다 범위: 0~제한 없음. | 미지정 |

**사용 예시**

```bash
jibsa zigbang search listings apt 역삼동 --trade 전세 --limit 20
```

**반환값**

지역 모드는 지역 집계, 반경 모드는 조회 단지 집계와 `listings`를 준다. 같은 호의 매물은 `listing_count`로 묶음을 설명한다.

**오류와 대응**

지원하지 않는 필터·면적 범위 위반은 `INVALID_ARGUMENT`. 반경 요청 예산 소진은 `notes`로 알린다.

**주의사항**

동·구 이름에 `--radius`·`--lat/--lng`를 주지 않으면 그 동·구 전체를 찾는다 (직방 지역 목록, 빠르고 빠짐 없음, `total` 은 동·구 전체 수, 거리 없음). 역 이름(동·구가 아닌 이름), 좌표, `--radius` 는 반경 안 단지를 가까운 순으로 훑는다 (기본 1km, 최대 2km). 역 이름이라 반경으로 바꿨으면 `notes` 로 알린다. 시·도 이름(서울·경기도)도 직방 지역 목록이 늘 0건이라 그 중심 반경으로 찾고 `notes` 로 알리니, 넓게 보려면 구 이름으로 찾는다. 구가 있는 시(성남시·수원시·창원시 등)는 시 대신 그 구들을 모두 찾아 합친다 (구마다 목록 요청, `--limit` 예산은 구끼리 나눠 번갈아 쓴다. `region.name` 은 `"성남시 분당구·수정구·중원구"`, `local_code` 는 쉼표로 잇고 `total` 은 구마다의 집계를 더한 값이다). 리(양근리)는 직방 지역 목록이 받지 않아 상위 읍·면(양평읍) 전체를 찾고 `notes` 로 알린다. 리 주변만 보려면 `--radius` 를 준다. 같은 이름의 동 없이 `○동N가` 로만 나뉜 동(성수동)은 그 동들을 모두 찾아 합친다 (동마다 목록 요청, `--limit` 예산은 아직 끝나지 않은 동끼리 나눠 번갈아 쓴다. `region.name` 은 `"성수동1가·성수동2가"`, `local_code` 는 쉼표로 잇는다. `total` 은 동마다의 집계를 더한 값이라 겹치는 매물이 두 번 세어질 수 있다. `--limit` 이 동 수보다 작으면 뒤쪽 동은 찾지 않고 `notes` 로 알리며, `region.name`·`local_code` 에는 찾은 동만 넣는다). 같은 이름의 동이 따로 있으면(당산동) 그 동만 찾고 빠진 `○가` 동을 `notes` 로 알린다. 아파트가 없는 작은 동은 직방 지역 목록이 이웃 동 단지를 대신 주기도 한다 (2026-10-10 실측: 문래동1가 목록은 모두 대림동·영등포동 단지). 동 이름으로 찾았는데 다른 동 단지가 섞이면 몇 건이 어느 동인지 `notes` 로 알리니 결과의 `address` 로 동을 확인한다 (구 단위 검색은 알리지 않는다).

직방 아파트 API 는 방 구조·층·욕실·옵션·관리비 조건이 없어 이 명령에도 없다. 거래 유형은 매매·전세·월세이며 단기임대는 지원하지 않는다.

면적(`--area-*`)은 다른 유형처럼 전용면적인데 직방 아파트 API 가 받지 않아 받은 뒤에 거른다. 동·구 전체에서는 받아 온 `--limit` 건 안에서만 걸러 맞는 매물이 더 있어도 적게 나올 수 있고, 그러면 `notes` 로 공급면적 조건을 쓰라고 알린다 (아파트 공급면적은 대개 전용면적의 1.1~1.5배다). 공급면적은 `--supply-area-min/max`(㎡)로 따로 준다. 동·구 전체 검색은 서버에서, 역·좌표·`--radius` 검색은 받은 매물에서 거른다 (공급면적이 없으면 제외, `total`은 공급면적으로 거르기 전 수). 전용면적과 함께 쓰면 두 조건을 모두 만족해야 한다. 공급면적 하한이 상한보다 크면 `INVALID_ARGUMENT`. 예: `jibsa zigbang search listings apt 역삼동 --supply-area-min 80 --supply-area-max 110`.

반경 검색은 가까운 단지부터 최대 30곳을 훑고, 면적 조건이 있으면 60곳까지 훑는다. 공급면적 조건이 있으면 단지마다 평형 목록을 먼저 받아(단지당 요청 1회 추가) 맞는 평형의 매물만 받는다. 그래도 반경 검색은 면적 조건에 맞는 단지가 멀리 있으면 놓칠 수 있어, 결과가 `--limit` 보다 적으면 동·구 이름과 `--supply-area-*` 로 찾으라고 `notes` 로 알린다 (2026-10-10 실측: 강남역 1km 안 공급 50㎡ 이하 매물 단지 3곳이 가까운 순 40·49·50번째였다). 작은 아파트는 동·구 이름으로 찾는다.

결과의 `complex_id`·`complex_name`·`supply_area_m2`로 단지와 공급면적을 확인하고 `id`로 상세를 본다. 같은 호를 묶은 결과와 제휴 매물은 [`listing`](#9-listing--매물-하나-상세)에서 설명한다.

**오류와 대응**

임대·매매 가격 조건 충돌, 면적 상한 이하 하한 등 잘못된 범위는 `INVALID_ARGUMENT`.

**주의사항**

동 이름은 경계 안, 그 밖의 위치는 반경을 기준으로 가까운 순으로 찾는다 ([`search listings room`](#2-search-listings-room--원룸빌라오피스텔-매물-찾기)과 같다). `--trade 임대`는 월세·전세를 포함하며 `--trade`는 하나만 받는다. 업종은 반복·쉼표로 지정하며 OR다. `--business` 를 주면 직방이 그 업종과 무관한 공실을 따로 주는데, 업종 조건을 지키도록 빼고 몇 건인지 `notes` 로 알린다. 공실도 보려면 `--business` 없이 검색한다.

가격 조건(`--deposit-*`, `--rent-*`, `--price-*`, `--manage-cost-*`, `--key-money-*`)은 모두 만원이고 하한·상한을 포함하며, 조합하면 모든 조건을 만족해야 한다. 보증금·월세·권리금 조건은 임대, 매매가 조건은 매매로 자동 좁히며, 서로 섞거나 `--trade` 와 충돌하면 `INVALID_ARGUMENT` 이다. 월세 조건은 월세 매물에만 적용하고 관리비 조건은 임대·매매 모두에 쓸 수 있다. `--area-max`는 지정 면적 미만이다.

가격은 서버 조건이 아니라 요약을 받은 뒤 거르고, 가까운 후보부터 일정 수까지만 확인한다. 조건을 건 금액이 `null` 이면 제외한다. `total_in_radius` 는 가격 적용 전 지도 후보 수다. 가격 조건이 있으면 `inspected_in_radius`(가격을 확인한 후보 수)와 `price_matched_in_radius`(그중 거래 가능하고 가격 조건에 맞는 수)를 함께 준다. 일부만 확인했으면 `notes` 로 알리며, 이때 전체 중 가격이 맞는 수는 모른다. 반경 밖 결과는 이 집계에 넣지 않는다. 예: `jibsa zigbang search listings store 역삼동 --deposit-max 5000 --rent-max 300 --key-money-max 3000` (2026-10-10 실측 15건. 무권리 `--key-money-max 0` 까지 걸면 역삼동·역삼역 모두 가까운 75건 안에 없어 0건이었다)

상세는 결과의 `store-…` ID를 그대로 `listing`에 넘긴다.

**주의사항**

월세가 아닌 주 단위 임대 서비스다. 금액 필드는 `weekly_rent_manwon`·`weekly_manage_cost_manwon`이며 매물 페이지는 직방 앱에서 열린다. `search listings room --trade 단기임대`(중개사가 올린 원룸·빌라 매물)와는 매물이 다르다.

동·구 등 지역 이름에 `--radius` 를 주지 않으면 그 지역 전체를 찾는다. 결과의 `boundary` 는 지역 이름이고 `total_in_radius` 는 지역 안 매물 수다. 역·학교 이름이나 `--radius` 를 주면 반경 안만, 좌표만 주면 지도에서 가까운 순으로 찾는다. 넓은 지역은 요청이 많아 느릴 수 있다. 같은 이름의 동 없이 `○동N가` 로만 나뉜 동(성수동)은 그 동들을 지역 전체로 모두 찾아 합친다 (동마다 검색 요청 1회 추가, `boundary` 와 `region.name`·`region.address` 의 동은 `"성수동1가·성수동2가"`). 같은 이름의 동이 따로 있거나(당산동) `--radius` 를 주면 한 동을 기준으로 찾고 빠진 `○가` 동을 `notes` 로 알린다. 구가 있는 시(성남시)는 그 구들을 모두 지역 전체로 찾아 합친다 (구마다 검색 요청 1회 추가, `boundary`·`region.name` 은 `"성남시 분당구·수정구·중원구"`). 리(양근리)는 직방 지역 검색이 상위 읍·면(양평읍) 전체를 찾아 `boundary` 가 읍·면 이름이고 `notes` 로 알린다. 리 주변만 보려면 `--radius` 를 준다. 세종의 동(반곡동)은 직방 단기임대 지역 검색이 찾지 못해, 원룸 검색처럼 그 동 경계(넓으면 중심 반경) 안을 지도로 찾고 `notes` 로 알린다.

가격·옵션·입주/퇴거일 조건은 서버에서 거르고, 고른 순서로 정렬한 뒤 `--limit` 를 적용한다. 정렬은 `distance`(거리), `price`(주당 임대료+관리비 합계), `newest`(등록 시각)이고 그 값이 없으면 뒤로 보낸다. 가격순은 할인·청소비·보증금을 넣지 않는다.

`--check-in`·`--check-out`은 함께 지정하고, `--check-out` 은 마지막으로 머무는 날이다. 직방 검색은 입주일과 마지막 날을 포함해 7~84일(1~12주)만 받아, 그 밖이면 요청 전에 `INVALID_ARGUMENT` 로 막는다 (2026-10-10 실측: 11-02~11-07 은 "최소 7일", 11-02~2027-01-25 는 "최대 12주(84일)"로 직방이 거절). `--flexibility`는 입주일과 함께 사용한다. 방 종류·할인·층은 OR, 옵션은 AND다. `--rooms 4`는 방 4개 이상이다. 상세와 기간 비용은 결과의 `stay-…` ID로 [`listing`](#9-listing--매물-하나-상세)에서 본다.

## 6. `complex` — 단지·건물 하나 정보

아파트 단지 또는 오피스텔 건물 정보를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 단지 ID. search locations 결과의 complexes[].complex_id 나 search 결과의 complex_id (예: apt-68579, officetel-20227) | 필수 |

**사용 예시**

```bash
jibsa zigbang complex apt-68579
```

**반환값**

- 아파트: 사용승인일·세대수·동 수·시공사·주차·용적률·난방, 거래 유형별 매물 수(`article_counts`), 평형 목록(`pyeongs`), 학군(`schools`, 배정 초등학교와 학교군 안 가까운 중·고등학교 2곳씩), 거주 후기 수(`review_count`)
- 오피스텔 건물: 세대수·층수·준공 연월(`completed_at`)·엘리베이터와 매물 수. `elevator` 는 있다고 확인될 때만 `true` 이고 그 밖에는 `null` 이다 (직방 건물 정보의 '없음'은 엘리베이터가 있는 고층 건물에도 붙어 믿을 수 없다). 정확한 값은 그 건물 매물의 `listing` 상세 `elevator` 로 본다

직방이 주는 정보가 달라 한쪽에만 있는 필드는 키가 없다.

**오류와 대응**

ID 접두사·형식 위반은 `INVALID_ARGUMENT`, 없는 단지·건물은 `NOT_FOUND`.

**주의사항**

단지 이름 대신 ID를 넣는다. 단지 ID 는 `search locations <단지 이름>` 결과의 `complexes[].complex_id`, `search listings apt`·`search listings room` 오피스텔 결과와 아파트 상세의 `complex_id` 에서 얻는다. 아파트 단지와 오피스텔 건물은 번호 체계가 달라 `apt-`·`officetel-` 을 붙인다.

`pyeongs[].id`는 `search listings --complex`·`real-price`의 `--pyeong`에 넣는 평형 ID이며 평수가 아니다. 후기는 본문을 내보내지 않고, 후기가 있으면 단지 페이지에서 보라고 `notes` 로 알린다. 관리사무소 연락처는 출력하지 않는다.

오피스텔은 `search listings room` 과 같은 관리비·방 구조·면적(전용 ㎡·평)·층·욕실·옵션·시설 조건도 서버에서 적용한다. 이 조건이나 `--without-random`을 아파트 ID와 함께 쓰거나, `--no-manage-cost`와 관리비 범위를 함께 쓰면 `INVALID_ARGUMENT`다.

```bash
jibsa zigbang search listings --complex officetel-20227 --trade 월세 --rent-max 100 --condition 엘리베이터
```

`--without-random`은 오피스텔 서버의 무작위 섞기를 끈다. 건물 매물은 서버가 준 순서 그대로이고, 써도 항상 같은 순서나 가격순·최신순을 보장하지 않는다.

아파트 결과는 `search listings apt` 와 같은 모양(같은 호·거래 유형을 묶은 매물)이다. 상세는 각 매물의 `id`로 `listing`을 사용한다.

## 8. `real-price` — 아파트 실거래가

아파트 단지의 실거래를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 아파트 단지 ID (search locations 결과의 complexes[].complex_id, search listings apt·listing의 complex_id, 예: apt-68579) | 필수 |
| `--trade` | 매매, 전세, 월세 중 하나 | 매매 |
| `--pyeong` | 평형 ID (complex 결과의 pyeongs[].id). 기본 전체 평형 범위: 1~제한 없음. | 미지정 |
| `--limit` | 최대 거래 수 범위: 1~1200. | 120 |

**사용 예시**

```bash
jibsa zigbang real-price apt-68579 --trade 매매 --pyeong 400085 --limit 20
```

**반환값**

단지·평형·거래 유형, `returned`, `has_more`, `transactions`, `url`을 준다.

**오류와 대응**

오피스텔 ID·범위·거래 유형 위반, 그 단지에 없는 `--pyeong` 은 `INVALID_ARGUMENT`. 없는 단지는 `NOT_FOUND` (거래가 아직 없는 단지는 오류 없이 0건이다).

**주의사항**

아파트 `apt-…` ID만 받는다 (오피스텔 건물은 `INVALID_ARGUMENT`). `--trade`는 매매·전세·월세 중 하나, 기본 매매다. 평형을 지정하지 않으면 전체 평형이며 `--pyeong`에는 `complex`의 `pyeongs[].id`를 넣는다.

실제 계약 가격·날짜를 최근 계약 순으로 조회한다. 호가나 기관 추정 시세와 구분해서 읽는다. 결과는 네이버·당근 `real-price` 와 같은 모양이고 `presale` 은 입주권·분양권 거래다. 직방은 전세·월세를 한데 묶어 줘서 한쪽만 고르면 받은 뒤 거르고 다음 페이지를 조회하므로, 거래가 부족하면 요청한 개수보다 적게 반환할 수 있다. 전세·월세는 최근 전월세 거래 1200건(24페이지)까지만 보고, 그 안에서 다 채우지 못하면 본 범위를 `notes` 로 알린다. 서버의 `hasNext`와 받은 결과로 `has_more`를 계산한다. `--limit`에서 멈췄으면 `notes`에서 `--limit`을 늘리라고 안내하고, 24페이지까지 보고도 더 오래된 거래가 남았을 때만 `url`의 직방 단지 페이지로 안내한다. 갱신 계약 여부는 직방이 주지 않아 `renewal` 이 항상 `null` 이다.

## 9. `listing` — 매물 하나 상세

조회 결과의 ID로 주거·상가·제휴·단기임대 상세를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `ITEM_ID` | 직방 매물 ID. 검색 결과의 id 그대로 (search 는 숫자, store 는 'store-123', stay 는 'stay-123', 아파트 제휴 매물은 'coalition-123') | 필수 |
| `--check-in` | 단기임대(stay-…)만: 입주일 (YYYY-MM-DD). --check-out 과 함께 주면 기간 비용·예약 가능 여부를 붙인다 | 미지정 |
| `--check-out` | 단기임대(stay-…)만: 마지막으로 머무는 날 (YYYY-MM-DD). 직방은 이 날까지 이용일로 센다 (1주 = 11-02~11-08). --check-in 과 함께 | 미지정 |
| `--pet` | 단기임대(stay-…)만: 반려동물 동반 (기간 비용에 반려동물 청소비가 붙는다) | 꺼짐 |

**사용 예시**

```bash
jibsa zigbang listing store-123
```

**반환값**

공통 상세 필드에 유형별 필드를 추가한다. 단기임대 날짜 지정 시 `period_cost`를 준다.

**오류와 대응**

거래 불가 매물은 `LISTING_UNAVAILABLE`. stay 전용 옵션을 다른 유형에 주거나 날짜·계약 기간이 잘못되면 `INVALID_ARGUMENT`.

**주의사항**

검색 결과의 `id`를 그대로 받는다. 숫자 ID는 주거 매물, `store-…`는 상가, `stay-…`는 주 단위 단기임대, `coalition-…`는 아파트 제휴 매물이다. 접두사를 임의로 제거하지 않는다.

가격·면적·방 구조·방향·입주일·관리비·주차·시설 등의 구조화 정보를 준다. 매물 유형별로 제공 필드가 다르다.

아파트 검색 결과는 같은 호·거래 유형을 올린 여러 매물을 하나로 묶은 것이다 (`listing_count`). `id` 는 그중 직방 매물 번호다. 묶음에 직방 매물이 없고 제휴 매물(호갱노노에 집주인이 내놓은 매물)만 있으면 `id` 가 `coalition-123` 이고, 같은 `listing` 으로 상세를 본다. 제휴 매물 상세는 등록일·주차·옵션·인근 역을 주지 않아 `null` 이고, 관리비는 확인 중인 경우가 많다. `url` 은 그 매물의 직방 웹 페이지다. 층은 `"저"`·`"중"`·`"고"` 로 오기도 한다.

`--check-in`·`--check-out`·`--pet`은 `stay-…` 전용이다. 날짜는 함께 지정하며 `--pet`(반려동물 청소비)에는 날짜도 필요하다. 날짜를 주면 직방 요금 계산으로 그 기간의 총비용을 `period_cost` 로 붙인다. `--check-out` 은 나가는 날이 아니라 마지막으로 머무는 날이다. 직방은 이 날까지 이용일로 세서 11-02~11-09 는 8일(1주+1일)로 하루치 요금이 더 붙는다 (2026-10-10 실측, 11-02~11-07 은 1주 미만으로 거절). `days`·`weeks`·`remaining_days` 로 몇 주 며칠로 계산됐는지 확인한다. 요금 계산은 예약 여부를 보지 않아, 같은 날짜로 매물 주변 지도를 다시 조회해 이 매물이 나오면 `available: true` 다 (`search listings stay` 의 `--check-in/--check-out` 과 같은 기준). 지난 입주일이나 매물의 최소·최대 계약 주 수를 벗어나면 `INVALID_ARGUMENT` 이고, 오류 힌트에 그 매물의 계약 범위(예: 1~12주)가 나온다. 최소 계약은 매물마다 달라 1주보다 긴 매물도 있다 (2026-10-10 실측 59건 중 7건이 2~8주, 최대는 모두 12주). 기간이 7~84일 밖이면 직방 지도 검색으로 예약 여부를 확인할 수 없어 `available: null` 이다. 예약 달력은 직방이 로그인한 사용자에게만 열어 줘서 보여 주지 않는다.

```bash
jibsa zigbang listing stay-123 --check-in 2026-11-02 --check-out 2026-11-29 --pet
```

## 조회 한도

아파트 검색(동·구·반경·`--complex apt-…`)의 `--limit`은 기본 20·최대 120이다. 요청당 동·구는 최대 20건, 반경·`--complex`는 최대 50건이며 실제 받은 원본 개수로 조회 예산을 센다. 중복·거래 불가·조건 불일치로 제외한 만큼 추가 조회하지 않는다. 반경 검색은 여러 단지를 합쳐 예산을 적용하고, 단지에서 적게 받으면 남은 예산을 다음 단지에서 조회한다. 결과 부족 및 최대값 도달 시 안내한다. 원룸 검색과 오피스텔 단지 검색도 기본 15·최대 120이며 같은 방식으로 확인한 매물 수로 예산을 세고 제외한 만큼 채우지 않는다. 상가는 가격 조건을 서버가 받지 않아 가까운 후보를 `max(limit × 5, 60)`건까지 확인해 결과를 채운다 (채우지 않으면 가격 조건을 건 검색이 거의 비어 온다). 단기임대는 기본 15·최대 120이고, 거리순은 가까운 `limit`건(역·학교 이름이면 위치를 모르는 검색 결과를 더해)만 확인한다. 반경 가격순·최신순과 지역 전체 거리순은 정렬 값이 요약에만 있어 반경(또는 지역) 안 후보를 모두 확인한 뒤 자르고, 지역 전체 가격순·최신순은 직방이 정렬해 준 앞 `limit`건만 확인한다. `search locations`은 후보 목록 각각 기본 120·최대 1200, `real-price`는 기본 120·최대 1200이다.

`--limit`은 최종 출력 개수의 상한이며 API 요청 한 번의 크기를 뜻하지 않는다. 유형마다 조회 방식·서버 필터·후처리·요청 상한이 달라 결과가 부족할 수 있다. 일부 조회·범위 밖 결과·지원하지 않는 유형은 `notes`를 확인한다. CLI에 `--offset`·`--cursor`는 없다. 새 검색에서 같은 목록·순서를 보장하지 않는다.

주거 매물의 거래 유형을 생략하고 월세·매매가·보증금 조건만 주면 거래 유형을 자동으로 좁힐 수 있고 `notes`로 알린다. `--trade`와 맞지 않는 가격 조건(전세 + `--rent-max` 등)은 [공통 규칙](common.md#출력-규칙)대로 입력 오류다. 월세와 단기임대는 별도 거래 유형이다.

## 출력 읽기

아래는 실제 매물을 포함하지 않은 **주요 필드 발췌 예시**다. 전체 응답에는 다른 매물 필드와 `notice` 등이 추가된다.

```json
{
  "returned": 1,
  "listings": [
    {
      "id": "store-123",
      "trade_type": "월세",
      "deposit_manwon": 3000,
      "rent_manwon": 150
    }
  ]
}
```

| 필드 | 용도 |
| --- | --- |
| 매물 `id` | `listing`에 그대로 전달 |
| `complex_id` | `complex`·`search listings --complex`, 아파트는 `real-price`에도 전달 |
| `pyeongs[].id` | 아파트 평형 필터 `--pyeong` |
| `returned` | 실제 반환 개수 |
| `boundary` / `radius_km` | 동·지역 경계 검색 또는 반경 검색 범위 |
| `notes` | 조회 범위·부족한 결과·정렬 등의 안내 |
| `url` | 원 사이트에서 확인·문의 |

집계 필드의 의미는 명령마다 다르다. 지도 후보 수나 서버 집계는 후처리한 실제 반환 수와 다를 수 있다. `search locations`은 검색 중심을 찾는 명령이라 지역 후보 좌표를 준다. 공통으로 읽는 법은 [공통 사용 규칙](common.md#반환값을-읽을-때)에 있다.

## 요청 제한과 도움말

요청 제한 정책과 `jibsa limits` 사용법은 [공통 사용 규칙](common.md#요청-제한과-limits)에 있다.

```bash
jibsa zigbang --help
jibsa zigbang search --help
jibsa zigbang search listings room --help
jibsa zigbang search listings --complex --help
```

유형별 옵션은 `room`·`apt`·`store`·`stay` 뒤에 지정한다. `search listings --complex <ID>` 모드와 유형별 하위 명령은 함께 사용할 수 없다. 기존 `items`·`item`·`search room|apt|store|stay` 별칭은 제공하지 않는다.

| 직방 단기임대 (`search listings stay`) | `weekly_rent_manwon`, `weekly_manage_cost_manwon`, `room_count`, `bathroom_count`, `discounts` | 주당 임대료·관리비(만원), 방·욕실 수, 할인 조건(예: `"4주 이상 10% 할인"`). 요금이 주 단위라 `rent_manwon`·`manage_cost_manwon` 키가 없다. 상세는 `deposit_manwon`·`cleaning_fee_manwon`·`min_contract_weeks`·`max_contract_weeks`·`max_guests`·`duplex`·`refund_policy` 도 준다. 상세에 `--check-in/--check-out` 을 주면 `period_cost` (그 기간의 이용 일수·주 수·남는 일수(`days`·`weeks`·`remaining_days`), 임대료·관리비·청소비·할인·직방 이용료·보증금·총액(만원)과 예약이 비어 있는지 `available`)가 붙는다 |

## 매물 해석 시 주의사항

아파트 넓이는 `area_m2`(전용면적)와 `supply_area_m2`(공급면적)를 구분한다. 같은 호를 묶은 목록의 가격은 최솟값일 수 있으므로 `is_price_range`·`listing_count`와 상세를 확인한다. 제휴 매물의 누락 정보는 없는 것으로 단정하지 않는다.

상세 `residence_type`에 `다가구`가 들어가면(`다가구`·`다가구주택`·`다가구용단독주택`) 건물 전체의 다른 세입자 선순위 보증금도 계약 전 확인한다. `근린생활시설`이 들어가면(`제2종근린생활시설` 등, 이른바 근생 원룸) 주거용 건물이 아니라 전입신고·전세대출·전세보증보험이 막힐 수 있으니 계약 전 확인한다. 등록일·입주일·주차는 조회 유형에 따라 제공 여부가 다르며 `null`을 없다고 해석하지 않는다.

상가 권리금은 `0`이면 무권리, `null`이면 모름이다. 단기임대의 주당 가격과 월세를 직접 비교하지 않고 날짜를 지정한 `period_cost`로 기간 비용을 확인한다. 단기임대 `url`은 개별 웹 매물 대신 안내 페이지이며 실제 매물은 직방 앱에서 확인한다.
