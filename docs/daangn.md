# 당근 부동산 CLI 사용법 (`jibsa daangn`)

[설치](https://github.com/Rukkakka/jibsa/blob/main/README.md) · [공통 사용 규칙](https://github.com/Rukkakka/jibsa/blob/main/docs/common.md) · [개발 가이드](https://github.com/Rukkakka/jibsa/blob/main/docs/development/providers/daangn.md)

> 금액은 **만원**, 면적은 **㎡** (1평 = 3.3㎡)다. 출력 형식·누락값·에러 대응·요청 제한 같은 공통 규칙은 [공통 사용 규칙](https://github.com/Rukkakka/jibsa/blob/main/docs/common.md)에 있고, 이 문서는 당근에만 있는 내용을 적는다.

## 한눈에 보기

| 명령 | 하는 일 | 무엇을 넣나 | 다음에 쓰는 곳 |
| --- | --- | --- | --- |
| `search locations` | 지역·역·대학·학교·단지 후보 찾기 (웹 지도 검색창) | 이름 또는 좌표 | search listings, complex, search listings --complex, school, preschools |
| `search listings` | 현재 매물 찾기 (웹 동 페이지·지도·역·대학 목록) | 동·구 이름, `--station` 역, `--university` 대학, `--address` 도로명 주소, `--lat/--lng` 좌표 | listing |
| `listing` | 매물 하나 상세 | 매물 ID | complex, real-price --item |
| `search complexes` | 지역·지도 범위 안 단지 목록 | 동·구 이름 또는 `--lat/--lng` 좌표 | complex, search listings --complex, real-price, preschools |
| `complex` | 단지 하나 정보 | 단지 ID | search listings --complex, real-price, price-trend, preschools |
| `search listings --complex` | 단지 안 현재 매물 | 단지 ID | listing |
| `real-price` | 단지·건물 실거래가 | 단지 ID 또는 --item 매물 ID | — |
| `region-real-price` | 동·구 실거래가·신고가 | 동·구 이름 | complex, real-price |
| `price-trend` | 월별 가격 추이 | 단지 ID | real-price |
| `school` | 학교·배정 단지 | 학교 이름 또는 학교 코드 | complex, search listings --complex, real-price |
| `search commute` | 회사까지 지하철 통근 매물 | 회사가 있는 동·구, `--station` 역, `--university` 대학, `--address` 주소 또는 좌표 | listing |
| `region-reviews` | 지역 후기 수·후기 많은 단지 | 동·구 이름 | complex |
| `preschools` / `preschool` | 단지 근처 어린이집·유치원 / 시설 하나 상세 | 단지 ID / 시설 번호 | preschool |
| `compare` | 단지 최대 10곳을 비슷한 크기 평형끼리 비교 | 단지 ID 여러 개 | complex, real-price |
| `nearby-complexes` | 같은 동의 다른 단지 | 단지 ID | compare, complex |
| `good-neighborhoods` | 라이프스타일별 살기 좋은 동 | 라이프스타일, 지역 | search listings |
| `trending-complexes` | 인기 급상승 단지 (전국·시·도·구) | 시·도·구 이름 (빼면 전국) | complex, compare |
| `popular-listings` | 구 안 조회수 많은 매물 | 동 이름 | listing |

### 보통 이렇게 이어서 쓴다

```text
search locations ─▶ search listings <지역> · --station <역> · --university <대학> ─▶ listing
search commute / popular-listings ─▶ listing
search locations / search complexes / school ─▶ complex ─┬─▶ search listings --complex ─▶ listing
                                       ├─▶ real-price
                                       └─▶ price-trend
listing ─▶ real-price --item (단지가 없는 건물)
trending-complexes / nearby-complexes ─▶ compare ─▶ complex · real-price
good-neighborhoods ─▶ search listings <법정동 이름>
search complexes / search locations ─▶ preschools <단지 ID> ─▶ preschool
```

## 옵션 읽는 법

명령 뒤에 검색어 또는 ID를 넣고, 그 뒤에 옵션을 붙인다. 이름에 공백이 있으면 따옴표로 감싸는 것이 가장 확실하다. 따옴표 없이 띄어 쓴 지역·단지 이름(`강남구 신사동`)은 한 이름으로 잇고([공통 규칙](https://github.com/Rukkakka/jibsa/blob/main/docs/common.md#출력-규칙)), 다른 소스와 달리 `--station`·`--university`·`--address` 도 값 뒤에 띄어 쓴 낱말을 그 값으로 잇는다 (`--address 테헤란로 152`, `--university 연세대학교 신촌캠퍼스`). 다음 옵션이 나오면 끝난다. `--station` 은 노선 이름(`서울5호선`·`신분당선`·`공항철도`) 뒤의 역 이름 한 낱말까지만 이어 `--station 서울5호선 양평역` 은 한 역이고, `--station 강남 역삼동`·`--station 강남역 역삼동` 의 `역삼동` 은 지역 이름으로 읽혀 함께 줄 수 없다는 `INVALID_ARGUMENT` 다. 단지·매물 ID는 결과에서 받은 값을 그대로 사용한다. 아래의 숫자 ID는 문법 설명용 가상 값이다.

단지 ID 를 받는 자리(`complex`·`real-price`·`price-trend`·`preschools`·`compare`·`nearby-complexes`·`search listings --complex`)에 단지·지역 이름처럼 숫자가 아닌 값을 주면 `INVALID_ARGUMENT` 이고, `hint` 가 단지 ID 를 찾는 법(`search complexes <동>`·`search locations <단지 이름>`)을 알린다.

여러 값을 받는 옵션은 쉼표 또는 반복 지정으로 쓸 수 있다. 한 값만 받는 `--approval`·`--deal`·실거래가의 `--trade` 등은 하나만 지정한다. 지원 값은 각 표에 있다.

지역 이름은 당근 웹 지도 검색창과 같은 지역 검색으로 찾고, 이름이 정확히 같은 법정동·구만 쓴다 (비슷한 이름을 대신 고르지 않는다). 같은 이름 지역이 여러 곳이면 이름 앞에 구·시·도를 붙인다 (`'강남구 신사동'`, `'서울 중구'`, `'성남시 분당구 정자동'`). 앞 낱말은 주소의 낱말 앞부분으로 맞춘다 ('강남' 은 강남구에 맞고 '남구' 는 강남구에 맞지 않는다). 시·도는 줄임말·옛 이름('서울시'·'강원도'·'전라남도')도 받는다. 다만 `광주시` 는 경기도 광주시만 가리킨다. 옛 광주광역시(지금 전남광주통합특별시)는 `전남광주` 나 구 이름(`광산구`)으로 준다. 같은 이름이 여러 곳이면 고르지 않고 `REGION_AMBIGUOUS` 로 후보(`candidates`)를 알린다. 이름이 같은 곳이 없고 비슷한 지역만 있으면 (`성수동` → 성수동1가·2가) 그것도 `REGION_AMBIGUOUS` 의 후보로 알리니 후보의 이름 그대로 다시 준다.

## 1. `search locations` — 지역·역·대학·학교·단지 후보 찾기

당근 웹 지도 검색창처럼 이름에 맞는 후보를 칸별로 준다. 고른 후보의 이름을 다음 명령에 그대로 넘긴다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `KEYWORD` | 지역·역·대학·학교·단지 이름 (예: 역삼동, 강남구, 역삼역, 연세대학교, 은마). --lat/--lng 를 주면 생략 | 미지정 |
| `--lat` | 중심 위도 (이름 대신) | 미지정 |
| `--lng` | 중심 경도 (이름 대신) | 미지정 |
| `--limit` | 최대 단지 후보 수. 다른 후보에는 적용하지 않음. 범위: 1~1200. | 20 |

**사용 예시**

```bash
jibsa daangn search locations 역삼
```

**반환값**

이름 검색은 `keyword` 와 칸별 후보를 준다 (기본 `--limit` 이면 요청 5회. 단지 후보는 50곳씩 받아 `--limit` 이 50곳을 넘으면 50곳마다 1회 더).

| 칸 | 내용 | 넘기는 곳 |
| --- | --- | --- |
| `results[]` | 지역: `level`(`시도`·`구`·`동`), `name1`·`name2`·`name3`, `region_id`. 시·도 → 구 → 동 순 | `search listings <지역>` 등 지역을 받는 명령 |
| `stations[]` | 지하철역: `name`(노선을 붙인 이름, 예: `서울2호선 역삼역`) | `search listings --station`, `search commute --station` |
| `universities[]` | 대학 캠퍼스: `name`(캠퍼스까지 붙인 이름), `address` | `search listings --university` |
| `schools[]` | 초·중·고: `name`, `address`, `school_code` | `school` |
| `complexes[]` | 단지: `complex_id`, `property_type`, `name`, `address` | `complex`, `search listings --complex` |

좌표 검색은 `lat`, `lng`, `results[]`(좌표가 속한 동)다.

**오류와 대응**

이름·좌표를 함께 주거나 좌표가 하나만 있으면 `INVALID_ARGUMENT`. 좌표 지도 쿼리 거절은 `UPSTREAM_ERROR`이며 힌트대로 이름 검색을 사용한다. 역·대학·학교·단지 칸의 검색이 실패하면(쿼리 거절·서버 오류) 다른 칸과 그때까지 받은 후보를 반환하고 실패 이유를 `notes`로 알린다. 실패한 역·대학·학교 칸과 하나도 받지 못한 단지 칸은 `[]`(후보 없음)가 아니라 `null`(모름)이다.

**주의사항**

후보는 앞부분이 비슷한 이름까지 모두 준다 (`역삼` → 역삼동). 다른 명령은 이름이 정확히 같은 곳만 찾으므로 후보의 이름을 그대로 넘긴다. 같은 이름 지역은 `name1`·`name2` 를 붙여 넘긴다 (`'강남구 신사동'`). 지역 후보는 법정동만 나온다 (행정동 `역삼1동` 은 없다). 같은 단지 이름이 다른 지역에도 있을 수 있으니 주소로 고른다.

`--limit`은 단지 후보에 적용하며 기본 20곳·최대 1200곳이다. 당근 단지 검색은 이름이 조금 비슷한 단지까지 이름이 맞는 순으로 주므로 찾는 단지는 앞쪽에 있다 ('헬리오시티' 100곳 중 관련 5곳이 1~5위). '○○아파트' 처럼 이름이 흔해 더 봐야 하면 `--limit` 을 늘린다. 단지 후보를 50곳씩 커서로 이어 받고, 더 남으면 조회 한도와 검색어 안내를 제공한다. 지역 후보는 100곳까지, 역 후보는 당근이 한 번에 주는 만큼 준다. 대학 후보는 50곳까지다. 당근 대학 검색은 다음 쪽을 주지 않아 50곳이 다 오면 뒤에 더 있을 수 있다고 `[일부]` `notes` 로 알리니, 찾는 캠퍼스·대학원이 없으면 그 이름까지 붙여 다시 찾는다. 학교 후보는 50곳까지이고 더 있으면 `[일부]` `notes` 로 알린다 (이름이 그대로 같은 학교가 먼저 온다). 흔한 이름(`중앙초등학교` 86곳)은 이름 앞에 지역을 붙여 다시 찾는다.

## 2. `search listings` — 현재 매물 찾기

당근 웹에서 매물 목록이 나오는 화면과 같은 목록으로 현재 거래 가능한 매물을 찾는다. 위치는 아래 중 하나만 준다.

| 위치 입력 | 당근 웹 화면 | 순서 |
| --- | --- | --- |
| 동 이름 (`역삼동`) | 지도에서 동을 누른 화면의 매물 목록 (그 동 매물만) | 최근 게시 순 |
| 구 이름 (`강남구`) | 지도에서 구를 연 화면의 매물 목록 (구 중심, 줌 12) | 최근 게시 순 |
| `--lat` `--lng` | 지도를 그 위치로 옮긴 화면의 매물 목록 (줌 15) | 최근 게시 순 |
| `--address` (`'테헤란로 152'`) | 검색창 주소 검색으로 찾은 도로명 주소의 좌표로 지도를 옮긴 화면의 매물 목록 (줌 15) | 최근 게시 순 |
| `--station` | 지하철역 화면의 역 주변 목록 | 당근 목록 순 (대체로 역에서 가까운 순) |
| `--university` | 대학 페이지의 대학 주변 목록. 조건이 하나도 없으면 웹처럼 원룸·투룸·오피스텔만 | 당근 목록 순 (대체로 대학에서 가까운 순) |
| `--complex` | 단지 화면의 매물 목록 ([6절](#6-search-listings---complex--단지-안-현재-매물)) | 단지 화면 순 |

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `REGION` | 동·구 이름 (예: 역삼동, 강남구, '강남구 신사동'). 동은 웹 지도에서 동을 누른 목록(그 동 매물만), 구는 웹 지도의 구 화면 범위 목록 | 미지정 |
| `--station` | 지하철역 이름 (예: 역삼역). 이름이 같은 역이 여럿이면 첫 역이고, 노선을 붙이면 그 역 (예: '서울5호선 양평역') | 미지정 |
| `--university` | 대학 이름 (예: 연세대학교). 캠퍼스가 여럿이면 캠퍼스까지 붙인다 (예: '연세대학교 신촌캠퍼스') | 미지정 |
| `--address` | 도로명 주소 (예: '테헤란로 152'). 당근 웹 검색창 주소 검색과 같이 후보를 찾아 그 좌표를 가운데에 둔 지도 화면 범위다. 후보가 여럿이면 `REGION_AMBIGUOUS` 로 알리니 후보의 도로명 주소 그대로 다시 준다 | 미지정 |
| `--complex` | 단지 ID. 지역·역·대학·주소·좌표·줌·세대수·주차대수 조건과 함께 사용할 수 없음. 범위: 1 이상. | 미지정 |
| `--lat` | 중심 위도 (지역 이름 대신) | 미지정 |
| `--lng` | 중심 경도 (지역 이름 대신) | 미지정 |
| `--zoom` | 구 이름·--lat/--lng·--address 로 찾을 때 웹 지도 줌 (8~18). 범위는 웹 데스크톱 지도 화면이다. 기본은 웹과 같다 (구 12, 좌표·주소 15: 약 1.6×1.7km). 1 작으면 가로·세로가 2배 | 미지정 |
| `--type / -t` | 아파트, 오피스텔, 원룸, 투룸, 주택, 상가, 사무실, 건물, 토지, 공장·창고. 반복하거나 쉼표로 구분. 기본 전체 (--complex 는 당근 웹 단지 화면처럼 아파트·주택·오피스텔·원룸·투룸, 조건이 하나도 없는 --university 는 원룸·투룸·오피스텔). 투룸은 투룸 이상 (쓰리룸·포룸 포함) | 미지정 |
| `--trade` | 매매, 전세, 월세, 단기임대, 연세 (1년치 월세를 한 번에 내는 제주 거래). 기본 전체 | 미지정 |
| `--deposit-min` | 보증금/전세금 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--deposit-max` | 보증금/전세금 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--rent-min` | 월세 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--rent-max` | 월세 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--yearly-rent-min` | 연세 하한 (만원, 1년치). --trade 연세 와 함께 범위: 0~제한 없음. | 미지정 |
| `--yearly-rent-max` | 연세 상한 (만원, 1년치). --trade 연세 와 함께 범위: 0~제한 없음. | 미지정 |
| `--price-min` | 매매가 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--price-max` | 매매가 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--with-manage-cost` | 월세 범위를 월세 + 관리비로 비교 (당근 "관리비 포함"). --rent-min/--rent-max 와 함께 | 꺼짐 |
| `--area-min` | 유형별 면적 하한 (㎡, 아래 주의사항 참고) 범위: 0~제한 없음. | 미지정 |
| `--area-max` | 유형별 면적 상한 (㎡, 아래 주의사항 참고) 범위: 0~제한 없음. | 미지정 |
| `--floor` | 층수: 반지하, 1층, 2~5층, 6~9층, 10층이상. 반복하거나 쉼표로 구분 | 미지정 |
| `--room-count` | 방 개수: 2개, 3개, 4개이상. 반복하거나 쉼표로 구분 | 미지정 |
| `--structure` | 방 구조: 오픈형, 분리형. -t 원룸 과 함께 | 미지정 |
| `--approval` | 사용승인일: 5년이내, 10년이내, 15년이내, 20년이내, 25년이내, 30년이내, 30년이상 중 하나 | 미지정 |
| `--deal` | 거래 방식: 직거래, 중개 (직거래 = 집주인이 직접 올린 매물) | 미지정 |

**사용 예시**

```bash

jibsa daangn search listings 역삼동 -t 원룸 --trade 월세 --deposit-max 1000 --rent-max 70 --next <앞 결과의 next>
jibsa daangn search listings --station 역삼역 -t 원룸 --trade 월세
jibsa daangn search listings --university '연세대학교 신촌캠퍼스' -t 원룸 --trade 월세 --limit 10
jibsa daangn search listings --lat 37.5004 --lng 127.0387 --zoom 14 -t 오피스텔
jibsa daangn search listings --address '테헤란로 152' -t 오피스텔 --trade 월세
jibsa daangn search listings 노형동 --trade 연세 --yearly-rent-max 1000
```

**반환값**

- 동: `region`(찾은 동), `total`(그 동에서 조건에 맞는 매물 수. 웹 지도의 동 거품 "매물 N개"와 같고 1000 에서 잘리지 않는다. 받지 못하면 `null`이고 이유를 `notes`로 알린다), `returned`, `has_more`, `next`, `listings`
- 구·좌표·주소 (지도 화면): `region`(구로 찾았으면 그 구, 좌표·주소면 화면 가운데의 동. 받지 못하면 `null`), 주소로 찾았으면 `address`(`road_address` 도로명 주소, `region_address` 지번 주소와 건물 이름, `place` 그 자리의 당근 단지·건물 이름, 단지면 `complex_id`, `lat`·`lng`), `zoom`, `width_km`·`height_km`(화면 범위), `total`(범위 안 당근 집계, 1000 에서 잘림), `returned`, `has_more`, `next`, `listings`
- 역: `region`(찾은 역의 이름·노선·좌표), `returned`, `has_more`, `next`, `listings`(매물마다 `walk_minutes`)
- 대학: `region`(찾은 캠퍼스 이름·주소·좌표), `returned`, `has_more`, `next`, `listings`

매물마다 `status`(`판매중`·`예약중`)가 있다. 예약중은 계약이 깨질 수 있어 당근 웹처럼 보여 준다. `next` 는 더 받을 매물이 있을 때만 있다. `distance_km` 는 동 중심·화면 가운데·역·대학까지의 직선거리이고 목록 순서와는 상관없다. 작성자가 주소를 숨긴 매물은 당근이 실제 위치가 아닌 좌표를 주어 `distance_km` 가 `null`(모름)이고 `notes` 로 알린다 (주소도 동까지만 온다).

같은 위치·조건에 `--next <결과의 next 값>` 을 붙이면 이어 받는다. 이어 받을 때는 지역·역·대학을 다시 찾지 않고 앞 결과가 찾은 곳에서 당근 목록 커서로 이어 간다. `region`·`total`·`distance_km` 은 앞 페이지와 같은 기준으로 준다.

**오류와 대응**

- 위치 입력(지역 이름·`--station`·`--university`·`--address`·`--lat/--lng`)을 둘 이상 주거나 하나도 주지 않으면 `INVALID_ARGUMENT`. `--zoom` 은 구 이름·좌표·주소에만, 세대수·주차대수 조건은 동·구·좌표·주소에만 쓴다 (역·대학 주변 목록은 이 조건을 받지 않아 결과가 조용히 틀리므로 막는다). 원룸 없는 `--structure`, 아파트·오피스텔 없이 다른 유형만 고른 세대수·주차대수 조건도 `INVALID_ARGUMENT`. 없앤 `--radius`·`--expand`·`--city` 를 주면 `hint` 가 지금 쓰는 법을 알린다.
- 같은 이름의 동·구가 여러 곳이면(신사동 → 강남구·은평구) `REGION_AMBIGUOUS` 로 후보를 알리니 구를 붙인다 (`'강남구 신사동'`). 구 이름까지 같은 동(태평로2가 → 서울·대구 중구)은 시·도까지 붙인다 (`'서울특별시 중구 태평로2가'`, `hint` 의 예시와 `candidates` 가 그 이름이다). `○가` 로 나뉜 동(`성수동`)은 합치지 않고 `REGION_AMBIGUOUS` 로 1가·2가를 고르게 한다. 시·도(`서울`), 구가 있는 시(`수원시`), 세종(`세종`)은 그 자체로는 찾지 않고 `REGION_AMBIGUOUS` 로 구·동 후보를 준다. 이름이 같은 곳이 없고 비슷한 지역만 있으면 그 지역을 후보로 주는 `REGION_AMBIGUOUS` 다.
- 행정동(`역삼1동`)은 `REGION_NOT_FOUND` 이고 힌트에 법정동 이름(`역삼동`)을 알려 준다. 리(`양근리`)도 당근 웹에 없어 `REGION_NOT_FOUND` 이고 상위 읍·면 이름이나 좌표를 안내한다. 역 이름(`강남역`)을 지역 자리에 주면 `REGION_NOT_FOUND` 의 힌트가 `--station` 을 알리고, 단지 이름이면 그 단지 ID 를 알린다 (비슷한 지역만 있어 `REGION_AMBIGUOUS` 이면 `hint` 끝에 덧붙인다). 도로명 주소는 `--address` 로, 건물 이름은 당근 주소 검색이 찾지 않으니 그 건물의 도로명 주소나 `--lat/--lng` 로 준다.
- `--address` 는 당근 주소 검색이 준 후보가 하나(또는 도로명·지번 주소가 입력과 정확히 같은 하나)일 때만 찾는다. 후보가 여럿이면(`테헤란로`) `REGION_AMBIGUOUS` 로 도로명 주소 후보(앞 5곳, `candidate_count` 는 받은 20곳까지)를 주니 그 주소 그대로 다시 준다. 20곳보다 많으면 `message` 가 `20곳이 넘습니다` 라고 알리니 시·구를 앞에 붙여 좁힌다. 후보가 없거나 당근이 그 주소의 좌표를 모르면 `REGION_NOT_FOUND`.
- 이름이 같은 역이 없으면 `REGION_NOT_FOUND`. 대학은 `search locations` 의 `universities[].name` 과 같은 이름이 하나면 그 캠퍼스다 (`고려대학교` 는 캠퍼스 이름이 없는 본교, `고려대학교 세종캠퍼스` 는 세종캠퍼스). 그런 이름이 없고 캠퍼스가 여럿이면(`연세대학교`) `REGION_AMBIGUOUS` 로 캠퍼스 이름을 주고, 이름이 같은 대학이 없으면 `REGION_NOT_FOUND` 의 힌트에 비슷한 대학을 준다. 당근 대학 검색은 50곳까지라 그보다 많으면 힌트가 잘렸을 수 있다고 알린다.
- 목록 옵션에 없는 값이나 다른 소스의 옵션을 옮겨 쓰면(`--option 반려동물`, `--condition 반려동물`, `--facility 엘리베이터`) 에러 `hint` 가 맞는 옵션(`--option 반려동물가능`, `--option 엘리베이터`)이나 당근에 그 조건이 없다는 것(`--bathroom`, `--direction`)을 알려 준다. `--next` 가 다른 위치·조건의 값이면 `INVALID_ARGUMENT` 다. 당근 웹이 쿼리를 바꿔 해시가 거절되면 `UPSTREAM_ERROR`다 (대신 찾는 경로는 없다).

**주의사항**

동 이름은 당근 웹 지도에서 동을 누른 목록처럼 그 동 매물만 최근 게시 순으로 조회한다. 조건이 있든 없든 같은 목록이다 (웹의 동 페이지 첫 화면은 조건 없이 주변 동 매물을 섞어 보여 주지만, 조건을 걸거나 지도에서 동을 누른 목록은 그 동만이다). 20건씩 받아 받은 원본 매물 수가 `--limit`에 도달하면 멈춘다. `distance_km` 는 동 중심에서 잰다.

구 이름·좌표·주소는 당근 웹 지도 화면 범위의 매물 목록이다. 주소는 당근 웹 검색창 주소 검색(도로명 주소 후보 → 그 주소의 좌표)으로 찾은 좌표를 가운데에 두고, 좌표 검색과 같은 줌 15 로 연다 (요청 2회 더). jibsa 는 화면이 없어 웹을 데스크톱 1440×900 창으로 열고 목록 패널을 띄웠을 때의 범위(지도 왼쪽 메뉴와 패널을 뺀 영역)를 쓴다. 줌 15 는 약 1.6×1.7km, 14 는 3.2×3.4km, 12 는 12.8×13.6km 다 (위도 37.5°). 범위는 사각형이라 구로 찾으면 이웃 구 매물도 섞이고 구 전체가 다 들어가지 않을 수 있다. 순서를 바꾸거나 범위 밖 매물을 붙이지 않는다.

역 주변 목록은 매물마다 역까지 도보 분(`walk_minutes`)을 붙여 당근 목록 순서로 준다. 요청당 100건씩 받아 받은 수로 예산을 세며 뺀 매물은 다시 채우지 않는다. 이름이 같은 역이 여러 곳이면(양평역은 경의중앙선·서울5호선) 당근 웹처럼 첫 역으로 찾고 다른 역을 `notes`로 알린다. 다른 역이면 `notes` 의 노선 붙인 이름을 그대로 `--station` 에 준다 (`--station '서울5호선 양평역'`). 대학 주변 목록도 같은 방식이고, 범위는 당근이 정한다. 대학 주변은 조건을 하나도 주지 않으면 당근 웹 대학 페이지처럼 원룸·투룸·오피스텔만 찾고 `notes` 로 알린다 (조건이 하나라도 있으면 그 조건 그대로, 종류를 안 고르면 전체).

`--structure`는 `-t 원룸`과 함께 쓴다. 세대수·세대당 주차 조건은 당근 웹처럼 `-t` 를 주지 않거나 아파트·오피스텔을 넣을 때 쓴다 (단지에 있는 매물에 걸린다). `--with-manage-cost`는 월세 범위를 월세+관리비로 비교한다 (`--rent-min`/`--rent-max` 없이 주면 `INVALID_ARGUMENT`). ㎡ 조건은 일반 매물의 전용면적, 주택·건물·공장·창고의 연면적, 토지의 대지면적을 사용한다. 서로 다른 유형을 함께 검색하면 면적 기준도 섞인다.

당근 목록(`search listings`)은 원래 번지·등록일·관리비·방 수를 주지 않아 `address` 가 동까지, `registered_at`·`manage_cost_manwon` 이 `null` 이다. `-t 투룸` 은 당근 카테고리대로 투룸 이상이라 목록의 `room_type` 이 `null` 이다. 목록의 원룸 `room_type`(오픈형·분리형)은 당근 원룸 구조라 방이 2개인 매물에도 붙을 수 있다. 상세(`listing`)에서는 번지까지 있는 지번 주소와 등록일, 관리비, 그리고 유형과 상관없이 방 수로 정한 `room_type`(방 2개 투룸, 3개 쓰리룸, 4개 이상 포룸이상)이 나온다. 방 1개는 원룸만 오픈형·분리형이고, 오피스텔·아파트 등은 구조를 몰라 `null`이며 `room_count`로 방 수를 확인한다.

`-t 원룸`은 당근의 원룸 카테고리(오픈형·분리형)를 찾는다. 당근 매물 종류는 작성자가 고른 하나라서, 같은 오피스텔 건물의 방 1개짜리도 원룸 또는 오피스텔로 갈린다. 아파트·오피스텔·주택으로 등록된 방 1개짜리 매물까지 찾는 조건이 아니고, 원룸으로 등록했어도 방이 2개인 매물이 있다. 빌라 원룸도 작성자가 원룸 카테고리로 등록한 경우에 포함되며 건축물의 법적 용도를 보장하지 않는다. 오피스텔 원룸을 빠짐없이 보려면 `-t 원룸,오피스텔`로 함께 찾는다. 모든 건물 유형의 방 1개짜리 집이 필요하면 해당 유형도 검색하고 `listing`의 `room_count`를 확인한다. `null`이면 방 수를 알 수 없다. 당근 웹처럼 `--room-count`는 2개·3개·4개 이상만 지원한다. `--structure`를 주면 당근은 거의 원룸만 돌려주므로 함께 준 다른 유형은 대부분 빠지고 `notes`로 알린다. 당근이 원룸 조건으로 돌려준 매물은 다른 유형으로 표시돼도 빼지 않으므로 결과의 `property_type`으로 확인한다. 원룸·투룸으로 등록됐지만 오피스텔·아파트 단지에 있는 매물은 빼지 않고 매물 ID·단지 이름·건물 종류를 `notes`로 알린다. `property_type`은 작성자가 고른 종류다.

금액·면적·세대수의 하한이 상한보다 크거나 유한하지 않은 숫자이면 조회 전에 `INVALID_ARGUMENT`로 거절한다. 조건은 당근 서버가 거르고 jibsa 는 받은 매물을 다시 거르지 않는다. 관리비 포함 월세도 서버에서 거르며 목록의 관리비는 `null`이다 (`null` 이어도 조건에는 맞고, `notes` 가 알린다. 금액은 `--details` 로 채운다).

거래 조건이 여러 개인 매물(예: 매매 + 월세)은 당근 웹 목록처럼 `--trade` 의 거래 유형으로 보여 줄 조건 하나를 고른다 (`--trade` 가 없으면 대표 조건, 겹치는 조건이 없거나 여럿이면 대표 조건 먼저). 금액은 다시 보지 않으므로 `--trade 매매,월세 --rent-max 50` 처럼 여러 거래 유형을 주면 매매 가격이 보일 수 있다. `--trade` 없이 금액 조건만 주면 당근 웹처럼 거래 유형을 고르지 않아 그 금액이 없는 다른 거래(월세 상한만 주면 전세·매매) 매물도 나오고 `notes`로 알린다. 한 거래 유형만 보려면 `--trade` 를 함께 준다. 준 `--trade` 에 금액 조건이 걸릴 유형이 없으면(전세 + 월세 상한, 월세 + 연세 상한) 서버가 조건을 무시하므로 `INVALID_ARGUMENT`다.

연세는 1년치 월세를 한 번에 내는 제주 거래다. `trade_type: 연세` 에 보증금 `deposit_manwon` 과 1년치 금액 `yearly_rent_manwon` 이 오고 `rent_manwon` 은 키가 없다 (월세가 아니다. 당근 웹처럼 월로 나눈 값도 주지 않는다). 결과에 연세 매물이 있으면 그 값으로 읽는 법을 `[참고]` `notes` 로 알린다 (`yearly_rent_manwon 1400 = 1년에 1,400만 원 (월세 아님)`). 연세만 찾으려면 `--trade 연세` 를, 금액 범위는 `--yearly-rent-min`/`--yearly-rent-max`(만원, 1년치)와 `--deposit-*` 를 준다. `--trade 연세` 에 `--rent-*` 를 주면 연세 범위 옵션을 알리는 `INVALID_ARGUMENT`, `--trade` 에 연세 없이 `--yearly-rent-*` 를 주면 `INVALID_ARGUMENT` 다. 당근 웹은 연세 조건을 제주에서만 보여 주지만 jibsa 는 지역을 가리지 않는다 (당근 서버가 어디서나 받는다). 제주 동 목록에는 연세 매물이 많다 (2026-11-13 실측: 노형동 40건 중 연세만 13건, 제주시 연동 40건 중 연세만 8건·월세+연세 2건). 아는 거래 조건(매매·전세·월세·단기임대·연세)이 하나도 없는 매물은 가격을 보여 줄 수 없어 빼고 그 수를 `[제외]` `notes` 로 알린다. `--details` 는 목록을 받은 뒤 그 거래 조건이 내려간 매물을 빼지 않고 `listing --trade` 처럼 대표 조건의 거래 유형·가격으로 바꿔 `notes` 로 알린다.

거래완료·숨김·노출 제한 매물은 내보내지 않는다. 비활성 중개소의 매물은 목록 카드에 중개소 상태가 없어 당근 웹처럼 목록에는 나오고, `listing`·`--details` 에서 막힌다 ([3절](#3-listing--매물-하나-상세)).

## 3. `listing` — 매물 하나 상세

검색한 매물의 현재 거래 조건과 구조화된 상세 정보를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `ITEM_ID` | 당근 매물 ID (search listings 결과의 id) 범위: 1~제한 없음. | 필수 |
| `--trade` | 보여 줄 거래 조건: 매매, 전세, 월세, 단기임대, 연세. search listings 결과의 trade_type 을 넘기면 목록과 같은 가격이 나온다. 기본은 대표 조건이고, 매물에 없는 조건이면 대표 조건을 보여 주고 notes 로 알린다 | 미지정 |

**사용 예시**

```bash
jibsa daangn listing 100001 --trade 월세
```

**반환값**

공통 상세 필드(`status`: `판매중`·`예약중` 포함)와 당근 전용 필드(`other_trades`, 관리비 항목, 중개보수, 관심 수, 해당 유형의 단지·권리금 정보)를 준다.

**오류와 대응**

거래 완료·숨김·삭제·노출 제한·비활성 중개소(`reason: BIZ_PROFILE_INACTIVE`, 당근 웹 상세의 "비활성화된 중개소의 매물이에요")·거래 조건 없음은 `LISTING_UNAVAILABLE`. 예약중은 막지 않고 `status` 로 알린다.

**주의사항**

검색 결과의 `id`를 넣는다. 여러 거래 조건이 있는 매물은 검색 결과의 `trade_type`을 `--trade`로 넘기면 같은 거래 조건의 가격을 볼 수 있다. 매물에 없는 거래 조건을 주면 에러 대신 대표 조건을 보여 주고 `notes` 로 알린다. 제주 연세 매물은 `trade_type: 연세` 에 `deposit_manwon`·`yearly_rent_manwon`(1년치)이 오고, 중개보수도 연세 거래의 값이다 ([2절](#2-search-listings--현재-매물-찾기)의 연세). 단지 매물은 `complex_id`로 단지 정보를 이어 조회할 수 있다.

## 4. `search complexes` — 지역 안 단지 목록

과거 실거래 조건으로 지역(동·구) 또는 좌표를 가운데에 둔 지도 화면 범위의 단지 후보를 고른다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `REGION` | 동 이름(예: '역삼동') 또는 구 이름(예: '강남구', '수원시 장안구'). 같은 이름이 여러 곳이면 '강남구 신사동' 처럼 구·시·도를 붙인다. `--lat/--lng` 를 주면 생략 | 미지정 |
| `--lat` `--lng` | 중심 좌표 (지역 이름 대신). 당근 웹 지도 단지 탭의 '이 영역 단지' 처럼 그 좌표의 지도 화면 범위 단지 | 미지정 |
| `--zoom` | `--lat/--lng` 로 찾을 때 웹 지도 줌 (8~18). 기본 15 (약 1.6×1.7km). 1 작으면 가로·세로가 2배 | 미지정 |
| `--type / -t` | 아파트, 오피스텔. 반복하거나 쉼표로 구분. 아파트는 주상복합 포함. 기본 전체 | 미지정 |
| `--trade` | 매매, 전세, 월세 중 하나. 가격 조건과 단지마다 붙는 최근 실거래의 거래 유형. 주지 않으면 매매로 보여 주되 웹처럼 거래 유형을 단지 조건으로 보내지 않는다 | 미지정 |
| `--deposit-min` | 보증금/전세금 하한 (만원, 전세·월세. 과거 실거래 기준) 범위: 0~제한 없음. | 미지정 |
| `--deposit-max` | 보증금/전세금 상한 (만원, 전세·월세. 과거 실거래 기준) 범위: 0~제한 없음. | 미지정 |
| `--rent-min` | 월세 하한 (만원, 월세. 과거 실거래 기준) 범위: 0~제한 없음. | 미지정 |
| `--rent-max` | 월세 상한 (만원, 월세. 과거 실거래 기준) 범위: 0~제한 없음. | 미지정 |
| `--price-min` | 매매가 하한 (만원, 매매. 과거 실거래 기준) 범위: 0~제한 없음. | 미지정 |
| `--price-max` | 매매가 상한 (만원, 매매. 과거 실거래 기준) 범위: 0~제한 없음. | 미지정 |
| `--area-min` | 전용면적 하한 (㎡, 1평=3.3㎡) 범위: 0~제한 없음. | 미지정 |
| `--area-max` | 전용면적 상한 (㎡) 범위: 0~제한 없음. | 미지정 |
| `--approval` | 사용승인일: 5년이내, 10년이내, 15년이내, 20년이내, 25년이내, 30년이내, 30년이상 중 하나 | 미지정 |
| `--household-min` | 세대수 하한 범위: 0~제한 없음. | 미지정 |
| `--household-max` | 세대수 상한 범위: 0~제한 없음. | 미지정 |
| `--parking-min` | 세대당 주차대수 하한 범위: 0~제한 없음. | 미지정 |
| `--sort` | 세대수, 가격높은순, 가격낮은순, 입주최신순, 입주오래된순 중 하나. 입주일 순은 사용승인일 순과 어긋날 수 있다 | 세대수 |

**사용 예시**

```bash
jibsa daangn search complexes '강남구 역삼동' -t 아파트 --sort 가격높은순
jibsa daangn search complexes --lat 37.5006 --lng 127.0366 --zoom 14 -t 오피스텔
```

**반환값**

`region`, `trade_type`, `sort`, `returned`, `has_more`, `complexes[]`를 준다. 좌표로 찾으면 `region` 은 화면 가운데의 동(모르면 `null`)이고 `zoom`·`width_km`·`height_km`(화면 범위)가 붙는다. 단지 카드는 현재 매물 수와 최근 실거래 요약을 포함한다.

**오류와 대응**

거래 유형과 가격 옵션이 충돌하거나 한도를 넘으면 `INVALID_ARGUMENT`. 지역 이름과 `--lat/--lng` 를 함께 주거나 둘 다 빼면, 지역 이름에 `--zoom` 을 주면 `INVALID_ARGUMENT`. 지역 미발견은 `REGION_NOT_FOUND`. 단지 이름(헬리오시티)을 주면 `REGION_NOT_FOUND` 의 `hint` 가 그 이름의 단지 ID·주소와 단지 명령(`complex`·`real-price`·`search listings --complex`)을 알린다 (단지 후보 요청 1회). 지역 검색이 단지 이름에 비슷한 지역을 주어 `REGION_AMBIGUOUS` 이면 지역 후보는 그대로 두고 `hint` 끝에 이름이 든 단지를 덧붙인다. 역 이름(강남역)을 주면 단지가 아니라 역이라고 알리고, 역이 있는 동 이름이나 다방·네이버 `search complexes <역 이름>` 으로 찾으라고 한다. 같은 이름의 동·구가 여러 곳이면 `REGION_AMBIGUOUS` 로 후보를 알리니 구·시·도를 붙인다 (`'강남구 신사동'`, `'서울 중구'`). 이름이 같은 곳이 없고 비슷한 지역만 있으면 그 후보를 주는 `REGION_AMBIGUOUS` 다. 구가 있는 시 이름(수원시)만 주면 시 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 구 후보(`candidates`, 예: `수원시 장안구`)를 알리니 그중 하나로 다시 찾는다. 시·도 이름(서울·경기도)만 주어도 시·도 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 그 시·도의 구 후보(`candidates`, 전체 수 `candidate_count`)를 알린다. 구가 없는 세종(`세종`·`세종시`)도 시 전체로는 조회할 수 없어 `REGION_AMBIGUOUS` 로 세종의 동 후보를 알린다.

**주의사항**

현재 매물 목록이 아닌 단지 목록이다. 동·구 이름은 웹 지도 단지 탭에서 지역 거품을 누른 목록, 좌표는 '이 영역 단지' 목록이다 (둘은 다른 API 지만 카드·조건·정렬이 같다). 좌표 범위는 지도 범위 매물 검색과 같은 데스크톱 화면 계산이라 사각형이고 이웃 동이 섞인다. 가격 조건과 가격 정렬은 단지의 과거 실거래 기준이다. 해당 가격의 현재 매물이 있는지는 `search listings --complex`로 확인한다. `--type`을 생략하면 도시형생활주택도 섞일 수 있다. 입주일 정렬은 사용승인일과 순서가 다를 수 있어 `notes`를 확인한다. `listing_counts`는 현재 거래 유형별 매물 수, `recent_trades`는 선택 거래 유형의 최근 실거래 요약이다.

서버에는 최대 50곳씩 요청하고 응답의 커서로 다음 페이지를 이어 받는다. 1200곳 조회 후에도 다음 페이지가 있으면 최대값 및 필터 안내를 제공한다. `--limit 1201`은 입력 오류다.

## 5. `complex` — 단지 하나 정보

단지의 평형·건물·학교·역 정보를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 단지 ID (위치 검색·단지 목록·매물 상세에서 받은 값). 범위: 1 이상. | 필수 |

**사용 예시**

```bash
jibsa daangn complex 100001
```

**반환값**

단지 ID·이름·주소·유형, 세대수·층수·주차·사용승인일·난방·시공사, `pyeongs`(평형마다 전용·공급면적, 방·욕실 수, `area_group` 전용면적 묶음, 아파트형 단지는 `pyeong` 공급 평형 묶음, `representative` 대표 평형), `nearby_subways`, `schools`, `listing_count`, `review_count`, `url`을 준다. 단지 공공 정보가 없으면 `pyeongs`·`nearby_subways`·`schools` 는 `null`(모름)이다.

**오류와 대응**

존재하지 않는 단지 ID는 `NOT_FOUND`. SSR 스토어를 읽을 수 없으면 `PARSE_ERROR`.

**주의사항**

단지 이름 대신 `search locations`·`search complexes`·`school` 또는 매물 상세의 `complex_id`를 사용한다. 평형·세대수·학교·역·현재 매물 수·후기 수 등을 제공한다. 당근 웹처럼 아파트형 단지(아파트·주상복합·재개발)는 평형을 공급 평 묶음(`pyeongs[].pyeong`, 예: 32평)으로 나누고, 그 밖은 전용면적 묶음(`pyeongs[].area_group`, 예: 84㎡)으로 나눈다. `pyeong` 은 `real-price`·`price-trend` 의 `--pyeong` 에, `area_group` 은 `--area` 에 넣는다. 전용 84㎡ 묶음에는 32평·33평처럼 공급 평형이 다른 평형이 섞이니 아파트는 `--pyeong` 으로 고른다. `schools` 는 배정 초등학교와, 당근 웹 학군 카드처럼 이 단지 주민이 많이 다니는 순(같으면 도보 순)으로 고른 중·고등학교 2곳씩이다 (도보 20분 안 학교, 없으면 가장 가까운 곳, 이 단지 주민이 다니는 곳). 주민이 다니면 `이 단지 N명 이상` 이 붙는다. 요청은 단지 페이지 1회(약 2MB)다.

**오류와 대응**

지역·역·대학·주소·좌표·줌·세대수·주차대수 옵션과 함께 주면 `INVALID_ARGUMENT`. 없는 단지는 `NOT_FOUND`.

**주의사항**

`search listings --complex <단지 ID>`는 2절 매물 검색의 단지 모드다. 단지 하나의 현재 매물을 당근 단지 화면의 매물 탭 순서로 조회한다. 지역 검색이 아니므로 `distance_km` 가 없고, 지역·`--station`·`--university`·`--address`·좌표·`--zoom`·세대수·주차대수 옵션은 함께 쓸 수 없다.

조건 옵션은 `search listings` 와 같고 당근 서버에서 건다. 거래 완료·숨김 매물은 빼고, 여러 거래 조건을 올린 매물은 `search listings` 처럼 `--trade` 의 거래 유형으로 보여 줄 거래를 고른다. `-t` 를 주지 않으면 당근 웹 단지 화면처럼 아파트·주택·오피스텔·원룸·투룸만 온다. 단지 안 상가·사무실 매물은 `-t 상가` 처럼 고른 때만 온다.

유형·방 구조·면적의 의미와 원룸 검색의 누락 가능성은 [검색 조건 주의사항](#2-search-listings--현재-매물-찾기)을 따른다.

## 7. `real-price` — 단지·건물 실거래가

단지 또는 매물이 속한 건물의 실거래를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 단지 ID (search locations <단지 이름> 의 complexes, 아파트·오피스텔 listing 의 complex_id). --item 을 주면 생략 범위: 1~제한 없음. | 미지정 |
| `--item` | 매물 ID. 단지 대신 그 매물이 있는 건물의 비슷한 면적 실거래를 본다 범위: 1~제한 없음. | 미지정 |
| `--trade` | 매매, 전세, 월세 중 하나 | 매매 |
| `--area` | 아파트형이 아닌 단지의 전용면적 묶음 (complex 결과의 pyeongs[].area_group, 예: 84). 단지로 볼 때만. 아파트형은 당근 웹처럼 --pyeong 으로만 고른다. 기본 전체 평형 범위: 1~제한 없음. | 미지정 |
| `--pyeong` | 공급 평형 묶음 (complex 결과의 pyeongs[].pyeong, 예: 32). 아파트형 단지만, 당근 웹 평형 탭과 같다. 기본 전체 평형 범위: 1~제한 없음. | 미지정 |
| `--limit` | 최대 거래 수 범위: 1~1200. | 120 |
| `--years` | 최근 몇 년 안 계약만 (오늘 기준) 범위: 1~30. | 기간 없음 |
| `--month` | 한 달의 계약만 (YYYY-MM, 예: 2026-08. 당근 웹 시세 그래프에서 달을 누른 목록). 단지로 볼 때만, `--years` 와 함께 쓰지 않는다 | 기간 없음 |

**사용 예시**

```bash
jibsa daangn real-price 100001 --trade 전세 --area 84 --limit 10
jibsa daangn real-price 100001 --pyeong 32 --years 3 --limit 1200
jibsa daangn real-price 100001 --pyeong 32 --month 2026-08
```

**반환값**

`trade_type`, `returned`, `has_more`, `transactions`, `url`; 단지 모드는 `complex_id` 와 `area_group`(`null` 이면 전체 평형. `--pyeong` 이면 대신 `pyeong`), 건물 모드는 `listing_id`를 준다. `--years` 를 주면 기간 시작일 `since`(이날부터 계약), `--month` 를 주면 `month`(YYYY-MM)도 준다. 전월세 거래의 계약 종류는 `contract_type`(`신규`·`재계약`)과 갱신요구권 사용 `renewal_right` 다 ([단지·건물 실거래 필드](#단지건물-실거래-real-price)).

**오류와 대응**

단지와 `--item` 동시 지정, 둘 다 누락, `--item`에 `--area`·`--pyeong`·`--month` 지정, `--area` 와 `--pyeong` 을 함께, `--month` 와 `--years` 를 함께, `YYYY-MM` 이 아닌 `--month` 는 `INVALID_ARGUMENT`. 아파트형이 아닌 단지에 `--pyeong` 을 주거나 단지에 없는 평형이면 `INVALID_ARGUMENT` 이고 `hint` 가 있는 평형을 알린다. 없는 단지는 `NOT_FOUND`, 사용 불가 매물은 `LISTING_UNAVAILABLE`.

**주의사항**

단지는 `COMPLEX_ID`, 단지가 없는 매물의 건물은 `--item`을 사용하며 둘을 함께 지정할 수 없다. `--area`·`--pyeong` 은 단지 조회에서만 사용한다. 평형을 주지 않으면 모든 평형의 거래다 (거래마다 면적이 있다. 당근 웹은 평형마다 따로 보여 준다). 아파트형 단지는 당근 웹처럼 `--pyeong`(공급 평형)으로만 고르고 `--area` 를 주면 `INVALID_ARGUMENT` 로 있는 평형을 알린다 (`--area 84` 같은 전용면적 묶음은 32평·33평을 섞어 웹 평형 탭과 달랐다. 2026-11-12 실측: 헬리오시티 84㎡ 매매 50건 중 28건이 33평). 아파트형이 아닌 단지(오피스텔·빌라)는 `--area` 로 고르고, 없는 묶음이면 `INVALID_ARGUMENT` 로 있는 묶음을 알린다. `--pyeong`·`--area` 는 평형 묶음을 확인하느라 요청이 1회 더 든다.

```bash
jibsa daangn real-price --item 100002 --trade 월세
```

최근 계약 순이다. 전세·월세는 최근 전월세 1200건 안에서 선택한 유형을 골라 결과가 부족할 수 있다. `--item`의 빈 결과는 그 건물의 거래가 없다는 확정이 아니라 당근이 해당 건물 실거래를 제공하지 않는 경우도 있다. 빈 결과면 `notes` 가 까닭을 가린다: `--years` 기간 앞에만 거래가 있으면 그렇다고 알리고, 전월세 거래는 있는데 고른 전세·월세가 없으면 받은 전월세 수를 알린다. `cancelled: true`는 해제된 거래로 시세·평균 계산에서 제외한다.

한 달만 보려면 `--month` 를 준다. 당근 웹 시세 그래프에서 달을 누르면 보내는 값(`tradeYearMonth`)이라 서버가 그 달 계약만 준다 (2026-11-12 실측: 역삼래미안 `--month 2026-08 --trade 월세` 8월 계약 11건). 매물 건물 실거래(`--item`)는 당근 쿼리에 그 변수가 없어 받지 않는다. 기간으로 보려면 `--years` 를 준다. 당근은 기간을 받지 않아 `--limit` 만 크게 주면 기간 밖 오래된 거래까지 모두 온다 (헬리오시티 84㎡ 매매 `--limit 1200` 은 2018년까지 938건, `--years 3` 은 468건에서 멈춘다). `--years` 는 최근 계약부터 넘기다 그 앞 거래가 나온 페이지에서 멈추고, `--limit` 도 함께 적용된다. 기본 120건·최대 1200건이다. 서버에 50건씩 요청하며 커서로 최대 24페이지를 조회한다. 추가 거래가 남으면(`--years` 면 그 기간 안에서) `has_more: true`다. `--limit`에서 멈췄으면 `notes`에서 `--limit`을 늘리라고 안내하고, 24페이지까지 보고도 남았거나 `--limit` 이 이미 1200이면 당근 사이트 확인을 안내한다. `--years` 를 줬는데 기간 시작일에 닿기 전에 멈췄으면 이 안내가 `요청한 기간(…부터) 중 YYYY-MM-DD 이전 거래는 받지 못했습니다` 로 어디까지 받았는지 알린다 (헬리오시티 월세 `--years 1` 은 최근 전월세 1200건이 2026-01-10 까지라 그 앞 두 달을 받지 못한다). 당근이 다음 페이지가 있다면서 이어 받을 페이지를 주지 않으면 그때까지 받은 거래만 주고 `[참고] 당근이 … 멈췄습니다` 와 당근 사이트 확인(`[일부]`)을 함께 안내한다. 응답이 바뀐 것일 수 있어 jibsa 업데이트가 필요할 수 있다는 말이 붙는다.

## 8. `region-real-price` — 동·구 실거래가·신고가

동·구의 최근 공개 실거래나 신고가 거래를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `REGION` | 동 이름(예: '역삼동') 또는 구 이름(예: '강남구', '수원시 장안구'). 같은 이름이 여러 곳이면 '강남구 신사동' 처럼 구·시·도를 붙인다 | 필수 |
| `--trade` | 매매, 전세, 월세 중 하나 | 매매 |
| `--new-high` | 이전 최고가를 넘은 신고가 매매만 (가격 높은 순). 당근 웹처럼 가장 최근 공개일 것만 | 꺼짐 |
| `--previous-days` | --new-high 와 함께: 이전 공개일의 신고가까지 (당근 웹은 최근 공개일만) | 꺼짐 |
| `--limit` | 최대 거래 수 범위: 1~1200. | 120 |

**사용 예시**

```bash
jibsa daangn region-real-price '서울 강남구' --new-high
jibsa daangn region-real-price 역삼동 --new-high --previous-days
```

**반환값**

`region`, `trade_type`, `new_high`, `sort`, `summary`, `returned`, `has_more`, `transactions`를 준다. `summary` 는 당근 웹 실거래 화면 머리의 요약(`data_date` 가장 최근 공개일, 그날의 `sale_count` 매매 수·`new_high_count` 신고가 수)이고 요청 1회가 더 든다 (받지 못하면 `null` 이고 `notes` 가 알린다). 각 거래의 계약일과 공개일을 구분한다. 매매 거래마다 당근 웹 카드와 같은 신고가 배지 `is_new_high` 와 직전 최고가 `previous_high_manwon`·`previous_high_date`·`previous_high_change_percent` 가 `--new-high` 없이도 온다 ([지역 실거래 필드](#지역-실거래-region-real-price)).

**오류와 대응**

전세·월세에 `--new-high` 를 지정하면, `--new-high` 없이 `--previous-days` 를 주면 `INVALID_ARGUMENT`. 없앤 `--sort` 를 주면 `hint` 가 정렬 규칙을 알린다. 지역 미발견은 `REGION_NOT_FOUND`. 단지 이름(헬리오시티)을 주면 `REGION_NOT_FOUND` 의 `hint` 가 그 이름의 단지 ID·주소와 단지 명령(`complex`·`real-price`·`search listings --complex`)을 알린다 (단지 후보 요청 1회). 지역 검색이 단지 이름에 비슷한 지역을 주어 `REGION_AMBIGUOUS` 이면 지역 후보는 그대로 두고 `hint` 끝에 이름이 든 단지를 덧붙인다. 역 이름(강남역)을 주면 단지가 아니라 역이라고 알리고 역이 있는 동 이름으로 찾으라고 한다. 구가 있는 시 이름(수원시)만 주면 시 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 구 후보(`candidates`, 예: `수원시 장안구`)를 알리니 그중 하나로 다시 찾는다. 시·도 이름(서울·경기도)만 주어도 시·도 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 그 시·도의 구 후보(`candidates`, 전체 수 `candidate_count`)를 알린다.

**주의사항**

아파트 단지 외에 빌라·오피스텔 같은 소규모 건물 거래도 섞인다. 이름이 동과 같으면 그 동, 아니면 같은 이름의 구를 본다. 구가 없는 세종(`세종`·`세종시`)은 세종특별자치시 전체 거래를 주고 `notes` 로 알린다. 리 거래 주소는 당근이 읍·면을 빼고 주며(`경기도 양평군 양근리`) 당근 웹 카드와 같게 그대로 준다 (예전에는 읍·면으로 조회하면 읍·면을 끼워 넣었다). 같은 이름의 동·구가 여러 곳이면 고르지 않고 `REGION_AMBIGUOUS` 로 후보를 알리니 구·시·도를 붙인다 (구는 시·도를 붙인다: `'서울 중구'`).

정렬 옵션은 없다. 매매는 당근 웹 실거래 화면과 같은 가격 순이다. 전체를 가격 순으로 세우는 것이 아니라 최근 공개일부터, 같은 공개일 안에서 가격 높은 순이다. 전세·월세는 당근이 가격 순을 받지 않아 최신 순(계약일이 아니라 최근 공개 순)이다 (당근 웹 실거래 화면에는 전세·월세가 없고, jibsa 가 같은 API 로 더 주는 것이다. 웹은 매매·전/월세 두 탭이고 jibsa 는 월세 유무로 전세·월세를 더 나눈다). 거래 취소(`cancelled`)는 웹처럼 매매·전월세 모두 표시한다. `--new-high`(이전 최고가를 넘은 신고가 매매만, 가격 높은 순)는 매매만 지원하고, 당근 웹 신고가 화면처럼 가장 최근 공개일의 신고가만 준다. 그날 신고가가 없으면 빈 목록이고 `notes` 가 알린다. 동처럼 좁은 지역은 자주 빈다 (2026-11-12 실측: 강남구 3건, 역삼동 0건). `--previous-days` 를 붙이면 이전 공개일의 신고가까지 최근 몇 달 치를 받는다 (같은 날: 강남구 27건, 역삼동 2건). 전세·월세는 당근이 섞어 주므로 최근 전월세 1200건 안에서 선택 유형을 고른다.

기본 120건·최대 1200건이다. 50건씩 커서로 최대 24페이지를 조회한다. 추가 거래가 남으면 `has_more: true`이고, `--limit`에서 멈췄으면 `--limit`을 늘리라고, 24페이지까지 보고도 남았거나 `--limit` 이 이미 1200이면 당근 사이트 확인을 안내한다. 당근이 다음 페이지가 있다면서 이어 받을 페이지를 주지 않으면 그때까지 받은 거래만 주고 `[참고] 당근이 … 멈췄습니다` 와 당근 사이트 확인(`[일부]`)을 함께 안내한다. 응답이 바뀐 것일 수 있어 jibsa 업데이트가 필요할 수 있다는 말이 붙는다.

## 9. `price-trend` — 월별 가격 추이

단지의 월별 평균 실거래가와 기간 변화율을 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 단지 ID (complexes·school·search locations <단지 이름> 결과, 아파트·오피스텔 listing 의 complex_id) 범위: 1~제한 없음. | 필수 |
| `--pyeong` | 공급 평형 묶음 (complex 결과의 pyeongs[].pyeong, 예: 32). 아파트형 단지만 범위: 1~제한 없음. | 대표 평형 |
| `--area` | 아파트형이 아닌 단지의 전용면적 묶음 (complex 결과의 pyeongs[].area_group, 예: 84). 아파트형은 당근 웹처럼 --pyeong 으로만 고른다. 범위: 1~제한 없음. | 대표 평형 |
| `--trade` | 매매, 전세 중 하나 (월세 시세 그래프는 없다) | 매매 |
| `--period` | 1년, 3년, 전체 중 하나 (당근 웹 시세 그래프 탭). 보여 줄 기간이자 변화율을 보는 기간 | 1년 |

**사용 예시**

```bash
jibsa daangn price-trend 100001 --pyeong 32 --trade 매매 --period 3년
```

**반환값**

`complex_id`, `trade_type`, `pyeong`(아파트형) 또는 `area_group`, `period`, `recent_average_manwon`·`recent_transactions`(웹 그래프 머리의 최근 3개월 평균과 거래 수), `kb_sale`(이 평형의 최근 KB 매매 시세: `low_manwon` 하위~`high_manwon` 상위 평균가와 조사 기준일 `survey_date`. 웹 그래프의 KB 시세 띠. 당근이 주지 않으면 `null`), `total_transactions`, `summary`(`start_month`·`start_average_manwon`·`end_month`·`end_average_manwon`·`months`·`change_percent`·`change_manwon`), `points`, `url`을 준다. `points`는 거래가 있는 달만 포함한다. `kb_sale` 은 전세 그래프에도 매매 시세가 온다 (KB 전세·월세 시세는 `compare` 의 `pyeong` 에 있다). 평형 묶음 정보가 없는 단지는 당근 웹처럼 시세 그래프가 없어(웹은 '아직 등록된 실거래가가 없어요') `pyeong`·`area_group` 이 없고 `points: []`·`total_transactions: 0`, `summary`·`recent_average_manwon`·`recent_transactions`·`kb_sale` 은 `null` 이며 `notes` 로 알린다.

**오류와 대응**

월세, 없는 기간, `--area` 와 `--pyeong` 을 함께 주거나 아파트형이 아닌 단지에 `--pyeong`, 아파트형(공급 평 묶음) 단지에 `--area`, 단지에 없는 평형은 `INVALID_ARGUMENT` 다. 아파트형 단지에 `--area` 를 주거나 없는 평형이면 `hint` 가 있는 평형을 알린다. 평형 묶음 정보가 없는 단지에 `--pyeong`·`--area` 를 주어도 `INVALID_ARGUMENT` 이고, 이런 단지는 시세 그래프가 없다고 `hint` 가 알린다. 없앤 `--years` 를 주면 `hint` 가 `--period` 를 알린다. 없는 단지는 `NOT_FOUND`. 기간 안 거래 달이 둘이 안 되면 오류 대신 `summary: null` 과 `notes` 로 알린다.

**주의사항**

당근 웹 단지 화면의 시세 그래프와 같은 데이터·계산이다. 매매·전세만 지원하며 월세 그래프는 없다. 웹처럼 평형 하나로 보고, `--pyeong`·`--area` 를 주지 않으면 웹이 처음 보여 주는 대표 평형이다 (`notes` 로 알린다). 크기가 다른 평형을 섞은 평균은 큰 평형 거래가 몰린 달에 튀어 쓰지 않는다. `--period` 는 표시 기간과 변화율 기간을 함께 정하며, 오늘이 든 달과 그 전 12·36·180개월이다. `points`는 거래가 있는 달만 오래된 순이며 `transaction_count`로 표본 수를 확인한다. 요청은 2회다 (단지 비교 칸 → 시세 그래프). 평형 묶음 정보가 없는 단지는 그래프를 받지 않아 1회다.

변화율(`summary`)은 웹 그래프처럼 기간 안 첫 거래 달과 마지막 거래 달의 평균가를 견준다 (`months` 개월간 `change_percent`%). 두 달 중 거래가 3건 미만인 달이 있거나 마지막 거래가 6개월 넘게 지났으면 `notes`로 알린다.

## 10. `school` — 학교·배정 단지

학교 정보와 배정 단지를 보고 학군 기준의 단지 후보를 찾는다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `NAME` | 학교 이름 (예: '역삼초등학교'. 일부만 줘도 된다) 또는 학교 코드 (예: B100000749). 여러 곳이면 후보의 school_code 로 다시 부른다 | 필수 |
| `--type / -t` | 아파트, 오피스텔. 반복하거나 쉼표로 구분. 아파트는 주상복합 포함. 기본 전체 | 미지정 |
| `--household-min` | 세대수 하한 (소규모 빌라형 단지를 뺄 때) 범위: 0~제한 없음. | 미지정 |
| `--limit` | 최대 단지 수 범위: 1~1200. | 120 |

**사용 예시**

```bash
jibsa daangn school 역삼초등학교 -t 아파트 --household-min 100
jibsa daangn school B100000749
```

**반환값**

`school`(`school_code` 포함), `total_complexes`(필터 후·한도 전), `returned`, `complexes`(당근 웹 학교 화면과 같은 순서), `url`을 준다.

**오류와 대응**

학교를 찾지 못하면 `NOT_FOUND` 이고, 당근 학교 이름에 시·도가 붙기도 해(`서울대치초등학교`) `hint` 가 줄이거나 시·도를 붙여 다시 찾으라고 한다. 이름이 들어간 학교가 여럿이면 고르지 않고 `REGION_AMBIGUOUS` 이고, `candidates` 에 학교마다 `name`·`address`·`school_code` 가 온다. 주소를 보고 고른 학교의 `school_code` 로 다시 부른다. 없는 학교 코드는 `NOT_FOUND`. 없앤 `--city` 를 주면 `INVALID_ARGUMENT` 이고 `hint` 가 학교 코드로 고르는 법을 알린다. 중·고등학교 배정 단지 없음과 단지 유형·세대수 조건에 맞는 배정 단지 없음은 정상 빈 목록과 `notes`다.

**주의사항**

당근 웹 검색창처럼 이름이 들어간 학교를 찾고 좌표가 없는 학교는 뺀다. 이름이 그대로 같은 학교가 하나뿐이면 그 학교다. `대치초등학교` 처럼 종류 이름까지 주고 이름이 그대로 같은 학교가 없으면 `대치초` 로도 한 번 더 찾아 합친다. 당근 검색은 `대치초등학교` 로 `서울대치초등학교` 를 못 찾아(당근 웹도 0건) jibsa 가 더하는 것이다 (요청 1회 더). 학교 코드는 `search locations <학교 이름>` 의 `schools[].school_code` 에도 있다. 배정 단지는 초등학교만 제공하고 중·고등학교는 학교 정보만 제공한다. 단지는 당근 웹 학교 화면과 같은 순서이고 소규모 빌라형 단지도 섞일 수 있다. 단지 유형·세대수 조건과 `--limit` 은 그 순서에서 거르고 자른다. 배정 단지 카드의 `recent_trades`는 웹처럼 취소되지 않은 최근 매매 1건이다. 학교 전화·좌표는 출력하지 않는다.

배정 단지는 기본 120곳·최대 1200곳을 표시한다. 일부만 표시하면 전체 개수와 표시 개수를 알리고, 최대값에서는 유형·세대수 조건으로 좁히도록 안내한다.

| `--price-min` | 매매가 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--price-max` | 매매가 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--with-manage-cost` | 월세 범위를 월세 + 관리비로 비교 (당근 "관리비 포함"). --rent-min/--rent-max 와 함께 | 꺼짐 |
| `--area-min` | 유형별 면적 하한 (㎡, [검색 조건 주의사항](#2-search-listings--현재-매물-찾기) 참고) 범위: 0~제한 없음. | 미지정 |
| `--area-max` | 유형별 면적 상한 (㎡, [검색 조건 주의사항](#2-search-listings--현재-매물-찾기) 참고) 범위: 0~제한 없음. | 미지정 |
| `--floor` | 층수: 반지하, 1층, 2~5층, 6~9층, 10층이상. 반복하거나 쉼표로 구분 | 미지정 |
| `--room-count` | 방 개수: 2개, 3개, 4개이상. 반복하거나 쉼표로 구분 | 미지정 |
| `--structure` | 방 구조: 오픈형, 분리형. -t 원룸 과 함께 | 미지정 |
| `--approval` | 사용승인일: 5년이내, 10년이내, 15년이내, 20년이내, 25년이내, 30년이내, 30년이상 중 하나 | 미지정 |
| `--deal` | 거래 방식: 직거래, 중개 (직거래 = 집주인이 직접 올린 매물) | 미지정 |
| `--option` | 기타 조건: 주차가능, 반려동물가능, 대출가능, 엘리베이터, 옥탑, 복층. 반복하거나 쉼표로 구분 | 미지정 |
| `--move-in-now` | 즉시 입주 가능한 매물만 | 꺼짐 |
| `--limit` | 역당 최대 매물 수 (100건씩 페이지를 넘겨 받는다) 범위: 1~120. | 5 |

역 주변 매물 목록은 단지 세대수·주차대수 조건을 받지 않아 `search listings` 의 `--household-min`·`--household-max`·`--parking-min` 이 없다. 단지 조건은 `search listings <동 이름> -t 아파트 --household-min …` 처럼 동 이름으로 찾는다.

**사용 예시**

```bash
jibsa daangn search commute --station 강남역 --max-minutes 20 -t 원룸 --trade 월세 --rent-max 70
jibsa daangn search commute --address '테헤란로 152' --max-minutes 20 -t 원룸 --trade 월세
```

**반환값**

`workplace_station`, `max_minutes`, `reachable_stations`(시간 상한 안에서 조건에 맞는 매물이 있는 역 수, 회사 역은 빼고 센다. 당근은 그런 역만 준다), `returned`, `unique_returned`, 역별 `stations[]`를 준다. 찾아본 역은 지하철 시간 짧은 순으로 모두 `stations[]` 에 있고(매물이 없는 역도), 역마다 지하철 시간·환승·편도 시간(`one_way_minutes`, 당근 웹의 "편도 N분" = 지하철 + 회사 역에서 회사까지 도보), 타는 역에서 회사 역까지 출근 방향 구간 `route[]`(`from_station`·`to_station`·`line`, 당근 출퇴근 지도의 역 상세 경로와 역·노선이 같다)와 그 역 주변 매물(`listings`)이 묶여 있다. 매물에는 역까지 도보 분이 붙는다. 같은 안내가 여러 역에 붙으면 `notes` 한 줄에 역을 모아 알린다 (모든 역이면 `찾아본 10곳 모두`).

**오류와 대응**

위치 입력(지역 이름·`--station`·`--university`·`--address`·`--lat/--lng`)이 없거나 둘 이상이면, 또는 지원하지 않는 조건 조합은 `INVALID_ARGUMENT`. 주소 처리는 `search listings --address` 와 같다 (후보가 여럿이면 `REGION_AMBIGUOUS`). 회사 위치에서 걸어서 60분 안에 지하철역이 없으면 당근 웹처럼 출퇴근 목록이 없어 `NOT_FOUND` 다. 위치 미발견 및 쿼리 거절은 에러의 힌트를 확인한다. 지역·역·대학 이름 처리는 `search listings` 와 같다 (같은 이름이 여러 곳이면 `REGION_AMBIGUOUS`).

**주의사항**

회사에서 가까운 역을 찾고 그 역까지 지하철로 갈 수 있고 조건에 맞는 매물이 있는 역 전부를 요청 1회로 받아(당근 웹 출퇴근 지도의 역 핀과 같다), 지하철 시간 짧은 역부터(같으면 당근 순서) 주변 매물을 보여 준다. 회사 역 자체의 주변 매물은 웹처럼 넣지 않으니 `search listings --station <회사 역>` 으로 따로 본다. `--max-minutes`는 총 통근 시간이 아니라 역 사이 지하철 시간의 상한이다. 당근은 지하철 60분 안 역까지만 주어 60을 넘게 주면 60분까지의 역만 찾고 `notes`로 알린다. `reachable_stations` 는 상한 안 역 전부를 센 수다. 상한 안에 역이 없으면 에러가 아니라 빈 결과에 회사 역 주변을 볼 명령을 `notes`로 알린다 (이름이 같은 다른 역으로 가지 않게 노선을 붙인 역 이름, 예: `--station '서울5호선 양평역'`). 가까운 역부터 최대 10곳을 조회하며 `--limit`은 전체가 아닌 역당 개수다. 기본 5건(10역이면 50건)·최대 120건을 받은 수로 세어 100건씩 다음 페이지를 이어 받고, 같은 역 안의 중복·거래 불가·거래 조건이 없는 매물은 제외해도 추가로 채우지 않는다. 여러 역에 걸친 같은 매물은 각 역에 유지한다. 결과는 `stations[]`로 묶이며 역 안의 매물은 당근이 준 순서 그대로다 (통근 시간으로 다시 세우지 않는다). `returned`는 역별 합계, `unique_returned`는 전체 서로 다른 매물 수다. 역 묶음의 `one_way_minutes` 는 당근 웹이 보여 주는 편도 시간(지하철 + 회사 역→회사 도보)이고 회사 도보를 모르면 `null` 이다. 문 앞까지 보려면 매물의 `walk_to_station_minutes` 를 더한다 (대기 시간은 없다. 예전의 합산 `commute_minutes` 는 웹에 없는 계산이라 뺐다). 지하철 시간을 모르는 역은 시간 상한을 확인할 수 없어 제외하고 안내한다. 환승 횟수를 모르면 `transfers`는 `null`이다.

당근 웹 출퇴근 지도는 회사 위치를 카카오 장소 검색으로 찾는다. 당근 API 가 아니라 jibsa 는 쓰지 않고, 당근 웹 검색창이 찾는 역·대학·도로명 주소(`--address`)의 좌표나 동·구의 중심을 회사 위치로 쓴다. 다른 곳이면 `--lat/--lng` 로 준다. 매물의 `distance_km`는 회사까지 직선거리다. 주소를 숨긴 매물은 `null` 이다. [통근 매물 필드](#통근-매물-search-commute)를 함께 확인한다.

유형·방 구조·면적의 의미와 원룸 검색의 누락 가능성은 [검색 조건 주의사항](#2-search-listings--현재-매물-찾기)을 따른다.

## 12. `region-reviews` — 지역 후기 수·후기 많은 단지

동네의 후기 유무·수와 후기 많은 단지를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `REGION` | 동 이름(예: '역삼동') 또는 구 이름(예: '강남구', '수원시 장안구'). 같은 이름이 여러 곳이면 '강남구 신사동' 처럼 구·시·도를 붙인다 | 필수 |
| `--top` | 후기 많은 단지 수 (당근 구 후기 페이지의 20곳까지) 범위: 1~20. | 20 |

**사용 예시**

```bash
jibsa daangn region-reviews '강남구 역삼동' --top 10
```

**반환값**

`region`, `has_reviews`, `review_count`, `top_complexes`, `url`을 준다. 후기 본문과 요약은 없다. `top_complexes` 는 구의 후기 페이지에서 받아 동으로 찾아도 구 전체에서 후기가 많은 단지이고 `notes` 로 알린다 (잠실동·문정동·가락동 모두 같은 목록).

**오류와 대응**

지역 미발견은 `REGION_NOT_FOUND`. 단지 이름(헬리오시티)을 주면 `REGION_NOT_FOUND` 의 `hint` 가 그 이름의 단지 ID·주소와 단지 명령(`complex`·`real-price`·`search listings --complex`)을 알린다 (단지 후보 요청 1회). 지역 검색이 단지 이름에 비슷한 지역을 주어 `REGION_AMBIGUOUS` 이면 지역 후보는 그대로 두고 `hint` 끝에 이름이 든 단지를 덧붙인다. 역 이름(강남역)을 주면 단지가 아니라 역이라고 알리고 역이 있는 동 이름으로 찾으라고 한다. 같은 이름의 동·구가 여러 곳이면 `REGION_AMBIGUOUS` 로 후보를 알리니 구·시·도를 붙인다 (`'강남구 신사동'`, `'서울 중구'`). 이름이 같은 곳이 없고 비슷한 지역만 있으면 그 후보를 주는 `REGION_AMBIGUOUS` 다. 구가 있는 시 이름(수원시)만 주면 시 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 구 후보(`candidates`, 예: `수원시 장안구`)를 알리니 그중 하나로 다시 찾는다. 시·도 이름(서울·경기도)만 주어도 시·도 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 그 시·도의 구 후보(`candidates`, 전체 수 `candidate_count`)를 알린다. 구가 없는 세종(`세종`·`세종시`)도 시 전체로는 조회할 수 없어 `REGION_AMBIGUOUS` 로 세종의 동 후보를 알린다. 구가 없는 지역은 가능한 조회 범위를 `notes`로 안내한다.

**주의사항**

후기 본문과 당근이 만든 동네 요약 글은 내보내지 않고, 내용은 `url`(당근 구의 동네 후기 페이지, 구가 없는 시는 동 지도 페이지)에서 보라고 `notes` 로 알린다. `top_complexes` 는 그 구에서 후기가 많은 단지(`complex_id`, 이름, 유형, 후기 수)다.

`review_count` 는 동·구의 실제 동네 후기 수다. 당근 웹 모바일 후기 화면의 '당근 앱에서 후기 N개 더 보기' 와 같은 수이고, 당근이 주지 않으면 `null` 이다 (2026-11-12 실측: 역삼동 1563개, 강남구 7132개). 지역 고르는 방식(같은 이름이면 구·시·도를 붙인다)은 [`region-real-price`](#8-region-real-price--동구-실거래가신고가)와 같다.

## 13. `preschools` / `preschool` — 어린이집·유치원

단지 근처 어린이집·유치원과 시설 하나의 운영 정보를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` (`preschools`) | 단지 ID (`search complexes`·`search locations <단지 이름>` 결과, 아파트·오피스텔 매물의 `complex_id`) | 필수 |
| `PRESCHOOL_ID` (`preschool`) | 시설 번호 (`preschools` 결과의 `id`) | 필수 |

**사용 예시**

```bash
jibsa daangn preschools 10697092
jibsa daangn preschool 37033
```

**반환값**

`preschools` 는 `complex_id`, `returned`, `preschools[]`(`id`, `name`, `distance_km` 단지에서 직선거리, `resident_count` 이 단지 주민 중 다니는 수, `review_count` 당근 설문 후기 수. 당근이 근처 시설 정보를 주지 않으면 `null`), `url`(당근 단지 페이지). `preschool` 은 어린이집·유치원 구분(`type`), 주소, 구·동, 운영 시간, 설립 유형(국공립·민간·직장 등), 설립·개원일, 관할 기관, 정원(`capacity`, 지금 다니는 원아 수가 아니다)·학급(`classes`)·교사(`teachers`) 수, 통학버스, 당근 학부모 설문 응답 수(`survey_responses`, 웹 '후기 N'. 설문이 없으면 0)다. 설문 내용은 `url` 이 없어 당근 앱에서 본다.

**오류와 대응**

단지 ID 가 아닌 값(지역·역 이름)이나 뺀 옵션(`-t`·`--radius`·`--lat`·`--lng`·`--limit`)을 주면 `INVALID_ARGUMENT` 이고 `hint` 가 단지 ID 를 찾는 법을 알린다. 없는 단지·시설 번호는 `NOT_FOUND`.

**주의사항**

당근 단지 화면 학군의 유치원 탭과 같은 목록·순서다. 이 단지 주민이 많이 다니는 곳이 먼저이고, 같으면 가까운 곳이 먼저다. 당근은 단지에서 1km 안의 시설을 가까운 순으로 20곳까지만 줘 `--limit` 이 없다. 20곳을 받으면 더 먼 시설이 있을 수 있어 `[일부]` 로 알린다 (2026-11-11 실측: 역삼동 단지는 1km 안 31곳 중 0.6km 안의 20곳, 양평 단지는 1km 안 11곳 모두). 출력 순서가 거리 순이 아니어서 잘린 것이 목록만으로는 보이지 않는다. 당근 웹에 위치·반경으로 찾는 기능이 없어 지역·역 이름으로는 찾지 않는다. 동네의 어린이집을 보려면 `search complexes <동>` 으로 단지를 찾아 관심 단지마다 부른다. 목록에는 어린이집·유치원 구분이 없어 `preschool` 로 본다. 당근이 근처 시설 정보를 주지 않은 단지는 `preschools: null`(모름)이고, 1km 안에 시설이 없으면 `preschools: []` 다. 둘 다 `returned: 0` 이고 `notes` 로 알린다 (당근 웹은 두 경우를 같은 빈 탭으로 보여 준다). 전화번호·홈페이지는 주지 않는다 (학교 정보와 같다). 초·중·고는 `school` 을 쓴다.

## 14. `compare` — 단지 나란히 비교

단지 여러 곳(최대 10)을 당근 웹 단지 비교처럼 평형 하나씩 같은 항목으로 비교한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_IDS` | 단지 ID 여러 개 (최대 10개) | 필수 |
| `--area` | 비교할 전용면적 (㎡, 예: 84). 모든 단지를 이 면적과 가장 비슷한 평형으로 본다 | 첫 단지 대표 평형 |

**사용 예시**

```bash
jibsa daangn compare 10697092 10699673 10697091
jibsa daangn compare 10697092 10667600 --area 84
```

**반환값**

`returned`, `complexes[]`. 단지마다 이름·유형·주소, 사용승인일, 동·세대수, 세대당 주차, 최저·최고 층, 현재 매물 수, `asking`(현재 평균 호가: `sale`·`jeonse`·`monthly_deposit` 마다 `average_manwon`·`count`), 관리비(`manage_cost_manwon` 비교한 평형의 월 관리비 추정, `manage_cost_per_m2_manwon`, `manage_cost_period`), 후기 수, 배정 학교(거리·도보), 주변 역(거리·도보), `pyeong`(비교한 평형: `pyeong`(아파트형)·`area_group`·`representative`·`type_name`·`households`·전용·공급면적, KB 시세 `kb_sale`·`kb_jeonse`·`kb_monthly`, 최근 실거래 `recent_sale`·`recent_jeonse`·`recent_monthly`. 거래 유형에 없는 금액 키는 빠져 전세는 `rent_manwon` 이 없다), `url`. 단지 공공 정보가 없으면 배정 학교·주변 역·`pyeong` 은 `null`(모름)이다.

**오류와 대응**

단지가 10개를 넘으면 `INVALID_ARGUMENT`, 없는 단지는 `NOT_FOUND`.

**주의사항**

단지마다 요청 1회다. 당근 웹 비교처럼 첫 단지는 대표 평형, 나머지 단지는 그 전용면적과 가장 비슷한 평형(묶음마다 세대수가 가장 많은 평형끼리 견주고, 같으면 대표 묶음)으로 비교한다. `--area` 를 주면 모든 단지를 그 면적에 맞춘다. 첫 단지에 평형 자료가 없으면 모든 단지를 대표 평형으로 본다. 웹은 매매·전세·월세를 탭으로 하나씩 보여 주지만 jibsa 는 한 번에 준다. `asking` 은 당근에 올라온 아파트 매물 앞 30건의 거래 유형별 평균 호가(0원 제외, 월세는 보증금 평균)라 실제 거래가는 `pyeong` 의 실거래를 본다. 최근 실거래는 그 평형의 매매 첫 건, 전월세 5건 중 전세·월세 첫 건이다. 관리비는 K-apt 의 받은 달 ㎡당 관리비 평균에 비교한 평형의 전용면적을 곱한 값이다. 단기임대는 세지 않는다. 후기 요약 글은 주지 않는다 (후기 수만). `pyeong.pyeong` 은 `real-price`·`price-trend` 의 `--pyeong` 에, 아파트형이 아닌 단지의 `pyeong.area_group` 은 `--area` 에 넣는다.

## 15. `nearby-complexes` — 같은 동 단지

기준 단지와 같은 동의 다른 단지를 세대수 많은 순으로 본다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 기준 단지 ID | 필수 |
| `--limit` | 최대 단지 수 범위: 1~1200. | 50 |

**사용 예시**

```bash
jibsa daangn nearby-complexes 10697092 --limit 20
```

**반환값**

`complex_id`, `region`(동), `total`, `returned`, `sort`(늘 `세대수`), `complexes[]`(`complex_id`, `name`, `type`, `households`, `listing_counts`: 매매·전세·월세별 현재 매물 수).

**오류와 대응**

없는 단지는 `NOT_FOUND`, 동을 모르거나 기타 유형인 단지는 `REGION_NOT_FOUND`.

**주의사항**

요청 3회다 (단지의 동 → 동의 단지 → 단지 카드). 당근 웹 단지 화면의 이 칸은 '함께 본 단지' 추천으로 바뀌어 같은 동 단지 목록은 웹 화면에 보이지 않고 검색 엔진용 본문에 단지 ID 순 10곳 링크로만 남았다. jibsa 는 그 쿼리와 지도 단지 카드 쿼리로 같은 동 단지를 모두 받아 세대수 순(`sort`)으로 준다 (웹처럼 기타 유형 단지는 뺀다). 같은 동 단지는 1200곳까지 한 번에 받고, 1200곳을 채우면 더 있을 수 있다고 `notes` 로 알린다. 가격 조건으로 단지를 고르려면 `search complexes` 를 쓴다.

## 16. `good-neighborhoods` — 살기 좋은 동 추천

당근 웹의 좋은 동네 추천처럼 라이프스타일 지표로 고른 동 5곳을 순위대로 본다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `--lifestyle` | 직장인자취, 대학생자취, 부부, 아이와함께, 반려동물과함께, 은퇴후 중 하나 | 필수 |
| `--region` | 시·도(예: 서울) 또는 시·군·구(예: 강남구, '서울 중구'). 시·도는 '서울시'·'충북' 같은 줄임말도 되고, 전남광주통합특별시(전남)는 광주·전남을 함께 찾고, 옛 이름(광주·광주광역시·전라남도)은 그 한 곳만 찾는다. 구가 있는 시는 '분당구'·'성남시 분당구' 로 한 구를, '수원시' 로 그 시의 구 모두를 찾는다. 반복하거나 쉼표로 구분 | 서울 |

**사용 예시**

```bash
jibsa daangn good-neighborhoods --lifestyle 직장인자취 --region 서울
```

**반환값**

`lifestyle`, `indicators`(쓴 지표 3개), `regions`, `returned`, `neighborhoods[]`(`rank`, `sigungu`, `dong`, `region_id`, `description` 한 줄 설명).

**오류와 대응**

`--lifestyle` 이 비었거나 둘 이상이면, 없앤 `--limit` 을 주면 `INVALID_ARGUMENT` (`hint` 가 바뀐 사용법을 알린다). 여러 시·도에 있는 시·군·구 이름(중구·서구 등)만 주면 `REGION_AMBIGUOUS` 로 후보(`candidates`)를 알려 준다. 시·도를 앞에 붙인다 (예: `--region '서울특별시 중구'`). 없는 지역은 `REGION_NOT_FOUND`.

**주의사항**

당근 웹처럼 늘 5곳이고, 지역은 하나 이상이어야 해 `--region` 을 주지 않으면 웹 첫 화면처럼 서울에서 찾고 `notes` 로 알린다 (당근 웹에는 전국 순위가 없다). 더 많은 동은 `--region` 을 바꿔 가며 본다. 지표는 당근 웹의 라이프스타일 카드와 같다 (예: 직장인자취 = 1인 가구 많은·교통 편리한·외식하기 좋은). `dong` 은 행정동(예: 역삼1동)이라, 매물은 법정동 이름(역삼동)으로 `search listings` 에서 찾는다. 동네 후기 요약 글은 주지 않는다.

## 17. `trending-complexes` — 인기 급상승 단지

당근 웹의 인기 급상승 단지처럼 어제 대비 오늘 조회가 급상승한 단지를 전국·시·도·구 안에서 본다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `REGION` | 시·도 또는 구 이름 (예: 서울, 강남구, '성남시 분당구'). 빼거나 '전국' 이면 전국. 동은 받지 않는다 | 전국 |

**사용 예시**

```bash
jibsa daangn trending-complexes
jibsa daangn trending-complexes 서울
jibsa daangn trending-complexes 강남구
```

**반환값**

`region`(`name`, `region_id`(전국은 `null`), `level`: `전국`·`시도`·`구`), `returned`, `complexes[]`(`rank`, `complex_id`, `name`, `type`, `address`, `households`, `approved_at`, 대표 평형 전용면적, 대표 평형 최근 매매가. 매매가가 0 으로 오면 당근 웹처럼 보여 주지 않아 `null`).

**오류와 대응**

동 이름을 주면 `INVALID_ARGUMENT` 이고 `hint` 가 그 동의 구로 찾는 명령을 알린다. 같은 이름의 동이 여러 곳이어도(`신사동`) 동을 고르게 하지 않고 `INVALID_ARGUMENT` 로 그 동들의 구를 시·도까지 붙인 이름으로 준다 (`'서울특별시 강남구' 또는 '서울특별시 은평구'`, `candidates`). 당근 웹도 동 단위 인기 급상승 단지는 없다. 지역 미발견은 `REGION_NOT_FOUND`, 같은 이름의 구가 여러 곳이면 `REGION_AMBIGUOUS` 로 후보를 알리니 시·도를 붙인다 (`'서울 중구'`).

**주의사항**

당근 웹의 인기 급상승 단지 더 보기 화면처럼 50곳까지 받아 `--limit` 이 없다 (2026-11-12 실측: 전국·서울 50곳, 강남구 13곳). 사진은 주지 않는다. 대표 평형은 웹처럼 대표 전용면적 묶음에서 세대수가 가장 많은 평형이다. 비면 `returned: 0` 이고 `notes` 로 나중에 다시 부르거나 `search complexes` 를 쓰라고 알린다. 단지가 없다는 뜻은 아니다. 사용승인 문구가 '입주 2020.08' 처럼 날짜가 아니면 `approved_at` 은 `null` 이다.

## 18. `popular-listings` — 조회수 많은 매물

동이 속한 구에서 조회수 순위가 높은 현재 매물을 본다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `DONG` | 동 이름 (예: 역삼동, '강남구 역삼동'). 순위는 그 동이 속한 구 전체다 (구가 없는 세종은 그 동 안) | 필수 |
| `--type` / `-t` | 원룸, 투룸, 아파트, 오피스텔 중 하나 (당근 웹 순위 화면이 받는 종류) | 전체 |
| `--limit` | 조회할 매물 수 (제외 전). 웹처럼 30위까지 범위: 1~30. | 30 |

**사용 예시**

```bash
jibsa daangn popular-listings 역삼동 -t 원룸
```

**반환값**

`region`, `returned`, `listings[]`(공통 매물 필드 + 조회수 순위 `rank`).

**주의사항**

당근 웹 순위 화면처럼 30위까지 본다 (서버는 100위쯤까지 주지만 웹에 없는 31위 뒤는 내지 않는다). 종류는 웹 순위 화면이 받는 원룸·투룸·아파트·오피스텔 중 하나만 받고(다른 종류나 둘 이상이면 `INVALID_ARGUMENT`. 쉼표로 잇거나 `-t` 를 되풀이해도 같다), 주지 않으면 전체 순위다 (웹에는 전체 순위 화면이 없지만 서버가 구 전체 순위를 준다). 구가 없는 세종은 그 동 안에서만 순위를 매겨(2026-10-11 실측: 새롬동 7건·반곡동 1건) 결과가 적고, `notes` 가 그 동 기준이라고 알린다. 받은 수로 예산을 세고 거래 불가로 뺀 매물은 다시 채우지 않으며, 뺀 매물의 순위 자리는 비운다. 매물 좌표가 없어 `distance_km` 는 없다. 같은 이름의 동이 여러 곳이면 고르지 않고 `REGION_AMBIGUOUS` 로 후보를 알리니 구를 붙인다 (`'강남구 신사동'`).

## 기본값과 조회 한도

| 명령 | CLI 기본 / 최대 |
| --- | --- |
| `search listings`, `search listings --complex` | 20 / 120건 |
| `search commute` | 역당 5 / 120건 (최대 10역, 역마다 100건씩 페이지를 넘긴다. 갈 수 있는 역 목록은 한 번에 전부) |
| `search complexes` (동·구·좌표 범위) | 120 / 1200단지 |
| `real-price`, `region-real-price` | 120 / 1200건 |
| `school` | 120 / 1200단지 |
| `nearby-complexes` | 50 / 1200단지 |
| `region-reviews --top` | 20 / 20단지 |
| `price-trend --period` | 1년 / 1년·3년·전체 |
| `search locations` | 20 / 1200단지 후보 (`--limit` 은 단지 후보에만 걸린다. 지역 후보는 100곳, 역 후보는 당근이 한 번에 주는 만큼, 대학·학교 후보는 50곳까지) |
| 역·대학 주변 `search listings` | 20 / 120건 (요청당 100건) |
| 지도 범위 `search listings` (구·좌표·주소) | 20 / 120건 (요청당 20건. 주소는 후보 20곳 안에서 하나) |
| `compare` | 단지 최대 10곳 |
| `good-neighborhoods` | 5동 (당근 웹과 같아 `--limit` 없음) |
| `popular-listings` | 30 / 30건 (당근 웹 순위 화면) |
| `listing`, `complex`, `preschools`, `preschool`, `trending-complexes` | `--limit` 없음 |

여기의 최대값은 CLI 정책이다. 서버가 요청 한 번에 반환할 수 있는 최대 개수와 같다는 뜻은 아니다. 검색 경로마다 페이지·후처리·조회 범위가 달라 결과가 요청한 개수보다 적을 수 있다. 동·단지 매물은 요청당 20건씩 최대 6페이지를 조회한다.

당근 목록 응답을 조회 한도 때문에 잘라내면 `notes`에 실제 조회된 개수와 표시 개수를 따로 안내한다. 예: “조회된 단지 75곳 중 --limit 50 에 맞춰 50곳만 보여 줍니다. --limit 을 최대 1200까지 늘리세요.” (`nearby-complexes`) 서버의 다음 페이지 표시가 없어도 초과 결과를 잘랐다면 안내하며, 중복·거래 불가·거래 조건이 없는 매물 제외 안내와 구분한다. 단지 후보·지역 단지·단지 매물은 남은 한도만큼만 요청해 서버가 더 주지 않으므로 이 안내 없이 `has_more`와 `--limit` 안내로만 알린다. 단지 후보·지역 단지·단지 매물이 다음 페이지가 있다면서 빈 페이지나 페이지 정보가 없는 응답을 주거나 커서가 없거나 되풀이되면 그때까지 받은 것만 주고 `[일부] 당근이 … 멈췄습니다` 로 알린다. 응답이 바뀐 것일 수 있어 jibsa 업데이트가 필요할 수 있다는 말이 붙는다 (`--limit` 을 늘려도 더 받지 못해 `--limit` 안내는 붙이지 않는다). 매물 목록(`search listings`, `search commute` 의 역별 매물)도 다음 쪽이 있다면서 빈 쪽을 주거나 커서가 없거나 되풀이되면 그때까지 받은 매물만 주고 같은 `[일부]` 안내로 알린다. 실거래가 멈출 때는 그 명령 절에 적었다.

| `has_more` | 해당 목록에 더 조회할 결과가 있는지 |
| `notes` | 조회 범위·제한·중복 이름·부족한 결과·정렬 안내 |
| 역 주변 `walk_minutes` | 매물에서 검색한 역까지 도보 분 (`search listings --station`) |
| `search locations` 의 `stations[].name`·`universities[].name` | `--station`·`--university` 에 그대로 전달 |
| 인기 매물·단지 `rank` | `popular-listings`·`trending-complexes` 의 순위 |
| 어린이집·유치원 `id` (`preschools`) | `preschool` 에 전달 |
| `pyeongs[].pyeong` (`complex`), `pyeong.pyeong` (`compare`) | 아파트형 단지의 공급 평형. `real-price --pyeong`·`price-trend --pyeong`에 전달 |
| `pyeong.area_group` (`compare`) | 아파트형이 아닌 단지만 `real-price --area`·`price-trend --area`에 전달 |
| 추천 동 `region_id` | 당근 동 ID. 매물은 법정동 이름으로 `search listings` 에서 찾는다 |
| `url` | 원 사이트에서 확인·문의 |

공통으로 읽는 법은 [공통 사용 규칙](https://github.com/Rukkakka/jibsa/blob/main/docs/common.md#반환값을-읽을-때)에 있다.

요청 제한 정책과 `jibsa limits` 사용법은 [공통 사용 규칙](https://github.com/Rukkakka/jibsa/blob/main/docs/common.md#요청-제한과-limits)에 있다. 당근 명령은 당근 요청만 쓴다 (다른 소스로 위치를 찾지 않는다). 웹 쿼리가 거절되면 대신 찾는 경로 없이 `UPSTREAM_ERROR` 로 끝나니 출력된 힌트와 업데이트 안내를 따른다.


## 소스별 반환 필드와 해석

[공통 사용 규칙](https://github.com/Rukkakka/jibsa/blob/main/docs/common.md#반환값을-읽을-때)과 함께 읽는다. 아래 필드는 조회 모드·유형에 따라 제공된다.

| 소스·조회 유형 | 필드 | 뜻 |
| --- | --- | --- |
| 당근 | `other_trades` | 보여 주는 조건 외에 함께 올라온 거래 조건 (만원, 예: `["전세 20000", "월세 1000/50", "연세 1000/1400"]`. 연세는 보증금/1년치). 없으면 `[]`. 기본은 대표 조건을 보여 주고 `listing --trade` 로 고른다 |
| 당근 연세 | `yearly_rent_manwon` | 연세 (만원, 1년치를 한 번에 낸다. 월세가 아니다). `trade_type: 연세` 에만 있고 그때 `rent_manwon` 은 키가 없다. 보증금은 `deposit_manwon` |
| 당근 | `manage_cost_excludes` | 관리비와 따로 내는 항목 (쓴 만큼 내는 전기·수도 등, 예: `["전기", "수도"]`). `manage_cost_includes` 는 관리비에 들어 있는 항목(예: `["공용"]`). 작성자가 항목을 밝히지 않았으면 둘 다 `null` |
| 당근 | `broker_fee_manwon` | 보여 주는 거래 조건의 중개보수 (만원, 부가세 포함). 당근이 법정 상한 요율로 계산한 값이라 실제는 협의로 더 낮을 수 있다. 직거래 매물은 키가 없다 |
| 당근 상가 | `key_money_manwon`, `key_money_negotiable` | 권리금 (만원, 직방 상가와 같은 이름)과 협의 가능 여부. `null` 은 작성자가 밝히지 않음. 협의 가능이면 권리금이 `1` 처럼 자리만 채운 값이기도 해서 금액을 그대로 믿지 않는다. 상가가 아니면 키가 없다 |
| 당근 | `watch_count` | 당근에서 이 매물을 관심 목록에 넣은 사람 수 (조회수가 아니다) |
| 당근 아파트·오피스텔 등 단지 매물 | `complex_id`, `complex_name`, `complex_type` | 단지 ID·이름·종류(아파트, 오피스텔, 주상복합 ...). 단지 ID 는 `daangn complex` 에 넘긴다. `complex_type` 은 당근 단지 종류라 작성자가 고른 `property_type` 과 다를 수 있다 (예: 원룸으로 올린 오피스텔 건물 매물). 이름에 "(도시형)"이 붙은 단지는 도시형생활주택인데 당근이 아파트·주상복합으로 분류해 그대로 나온다. 단지가 없는 원룸·빌라 등은 키가 없다 |

### 통근 매물 (`search commute`)

타는 역과 그 역에서 회사 역까지 지하철 시간(분)·환승 횟수·편도 시간·경로는 매물마다 붙지 않고 매물이 들어 있는 역 묶음(`stations[]` 의 `station_name`·`subway_minutes`·`transfers`·`one_way_minutes`·`route`)에 있다. `route[]` 는 출근 방향 구간 목록이다. 구간마다 타는 역(`from_station`)에서 내리는 역(`to_station`)까지 한 노선(`line`)으로 가고, 첫 구간은 묶음의 `station_name` 에서 시작해 마지막 구간은 회사 역(`workplace_station`)에서 끝난다. 구간 수는 환승 + 1 이다 (예: 남부터미널역 → 교대역 서울3호선, 교대역 → 강남역 서울2호선). 당근 웹 역 상세는 같은 역·노선을 회사 역부터 그린다. 당근이 경로를 주지 않았거나 경로 모양이 달라 읽을 수 없으면 `null` 이다.

| 필드 | 뜻 |
|---|---|
| `walk_to_station_minutes` | 매물에서 타는 역까지 도보(분). 당근이 모르면 `null` |

## 매물 해석 시 주의사항

상세의 `options`에 있는 “대출 가능”은 작성자가 전세자금대출 가능으로 표시한 것이며 융자 여부가 아니다. 실제 대출은 계약 전 은행에서 확인한다. “전입신고 가능”도 작성자가 표시한 것이라 건물 용도와 함께 계약 전에 확인한다.

동 이름 검색은 그 동 매물만 주지만, 지도 범위 검색(구·좌표·주소)은 사각형 범위라 이웃 동·구가 섞이고 역·대학 주변 목록도 여러 동에 걸치므로 각 매물 주소를 확인한다.

비교 구간이 적거나 오래된 가격 추이는 `notes`와 거래 수를 함께 설명한다.
