# 당근 부동산 CLI 사용법 (`jibsa daangn`)

[설치](../README.md) · [공통 사용 규칙](common.md) · [개발 가이드](../references/providers/daangn.md)

> 금액은 **만원**, 면적은 **㎡** (1평 = 3.3㎡)다. 출력 형식·누락값·에러 대응·요청 제한 같은 공통 규칙은 [공통 사용 규칙](common.md)에 있고, 이 문서는 당근에만 있는 내용을 적는다.

### 보통 이렇게 이어서 쓴다

```text
search listings / search commute / popular-listings ─▶ listing
search locations / search complexes / school ─▶ complex ─┬─▶ search listings --complex ─▶ listing
                                       ├─▶ real-price
                                       └─▶ price-trend
listing ─▶ real-price --item (단지가 없는 건물)
trending-complexes / nearby-complexes ─▶ compare ─▶ complex · real-price
good-neighborhoods ─▶ search listings <법정동 이름>
developments ─▶ development · preschools ─▶ preschool
```

## 옵션 읽는 법

명령 뒤에 검색어 또는 ID를 넣고, 그 뒤에 옵션을 붙인다. 이름에 공백이 있으면 따옴표로 감싼다. 단지·매물 ID는 결과에서 받은 값을 그대로 사용한다. 아래의 숫자 ID는 문법 설명용 가상 값이다.

여러 값을 받는 옵션은 쉼표 또는 반복 지정으로 쓸 수 있다. 한 값만 받는 `--approval`·`--deal`·실거래가의 `--trade` 등은 하나만 지정한다. 지원 값은 각 표에 있다.

`--city` 는 같은 이름의 지역·역·학교를 시·도나 구 이름(앞부분)으로 좁힌다. 시·도는 줄임말·옛 이름('서울시'·'강원도'·'전라남도')도 받는다. 다만 `광주시` 는 경기도 광주시만 가리킨다. 옛 광주광역시(지금 전남광주통합특별시)는 `전남광주` 나 구 이름(`광산구`)으로 준다 (`광주` 는 두 곳 모두에 맞는다). 같은 이름의 동·구가 여러 곳이면(`--city` 를 줬는데도 여러 곳이 맞으면 포함) 고르지 않고 `REGION_AMBIGUOUS` 로 후보(`candidates`)를 알리니 `--city` 를 주거나 구 이름으로 좁힌다. 역·학교는 첫 곳으로 찾고 `notes` 로 알린다.

## 1. `search locations` — 지역·단지 후보 찾기

지역과 전국 단지 후보를 찾아 다음 조회에 쓸 ID를 고른다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `KEYWORD` | 동 이름 (예: 역삼동) 또는 단지 이름. 구 이름이면 그 구의 동 목록. --lat/--lng 를 주면 생략 | 미지정 |
| `--lat` | 중심 위도 (동 이름 대신) | 미지정 |
| `--lng` | 중심 경도 (동 이름 대신) | 미지정 |
| `--limit` | 최대 단지 후보 수. 지역 후보에는 적용하지 않음. 범위: 1~1200. | 120 |

**사용 예시**

```bash
jibsa daangn search locations 역삼동
```

**반환값**

이름 검색은 `keyword`, `results[]`(지역 후보)·`complexes[]`(단지 후보), 좌표 검색은 `lat`, `lng`, `results[]`다.

**오류와 대응**

이름·좌표를 함께 주거나 좌표가 하나만 있으면 `INVALID_ARGUMENT`. 좌표 지도 쿼리 거절은 `UPSTREAM_ERROR`이며 힌트대로 이름 검색을 사용한다. 이름 검색의 단지 검색이 실패하면(쿼리 거절·요청 제한·서버 오류) 지역 후보와 그때까지 받은 단지 후보를 반환하고 실패 이유를 `notes`로 알린다.

**주의사항**

이름 검색은 지역 후보 `results[]`와 전국 단지 후보 `complexes[]`를 함께 준다. 같은 단지 이름이 다른 지역에도 있을 수 있으니 주소로 고른다. 구 이름은 그 구의 동 목록을 찾는 데 쓸 수 있다. 좌표 검색은 좌표가 속한 지역을 찾으며 단지 후보 검색과 다르다.

`--limit`은 단지 후보에 적용하며 기본 120개·최대 1200개다. 지역 후보는 그대로 반환한다. 단지 후보를 50개씩 커서로 이어 받고, 더 남으면 조회 한도와 검색어 안내를 제공한다.

## 2. `search listings` — 현재 매물 찾기

동의 최근 매물 또는 위치 주변의 현재 거래 가능한 매물을 찾는다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `--complex` | 단지 ID. 지역·좌표·반경·주변 동·세대수·주차대수 조건과 함께 사용할 수 없음. 범위: 1 이상. | 미지정 |
| `DONG` | 동 이름 (예: 역삼동). 역 이름(예: 역삼역)이면 당근 역 주변 매물, 장소 이름이면 그 위치 반경으로 찾는다. --lat/--lng 를 주면 생략 | 미지정 |
| `--lat` | 중심 위도 (동 이름 대신) | 미지정 |
| `--lng` | 중심 경도 (동 이름 대신) | 미지정 |
| `--radius` | 검색 반경 (km, 기본 1). 주면 동 이름도 그 위치 반경으로 찾는다. 반경 안 매물이 모자라면 반경 밖 가까운 매물도 나온다 범위: 0.1~5.0. | 미지정 |
| `--city` | 동·역 이름이 여러 곳일 때 시/도나 구로 좁힘 (예: '강남구', '경기도'. 시·도는 '서울시'·'강원도' 같은 줄임말도 된다). 장소 이름·반경 검색에는 쓰지 않는다 | 미지정 |
| `--expand` | 주변 동을 몇 개 더 조회할지. 당근 피드에 섞여 오는 주변 동부터 고르고 (구 경계를 넘을 수 있음), 모자라면 같은 구의 다른 동으로 채운다 범위: 0~10. | 0 |
| `--type / -t` | 아파트, 오피스텔, 원룸, 투룸, 주택, 상가, 사무실, 건물, 토지, 공장·창고. 반복하거나 쉼표로 구분. 기본 전체. 투룸은 투룸 이상 (쓰리룸·포룸 포함) | 미지정 |
| `--trade` | 매매, 전세, 월세, 단기임대. 기본 전체 | 미지정 |
| `--deposit-min` | 보증금/전세금 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--deposit-max` | 보증금/전세금 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--rent-min` | 월세 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--rent-max` | 월세 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--price-min` | 매매가 하한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--price-max` | 매매가 상한 (만원) 범위: 0~제한 없음. | 미지정 |
| `--with-manage-cost` | 월세 범위를 월세 + 관리비로 비교 (당근 "관리비 포함") | 꺼짐 |
| `--area-min` | 유형별 면적 하한 (㎡, 아래 주의사항 참고) 범위: 0~제한 없음. | 미지정 |
| `--area-max` | 유형별 면적 상한 (㎡, 아래 주의사항 참고) 범위: 0~제한 없음. | 미지정 |
| `--floor` | 층수: 반지하, 1층, 2~5층, 6~9층, 10층이상. 반복하거나 쉼표로 구분 | 미지정 |
| `--room-count` | 방 개수: 2개, 3개, 4개이상. 반복하거나 쉼표로 구분 | 미지정 |

| `--deal` | 거래 방식: 직거래, 중개 (직거래 = 집주인이 직접 올린 매물) | 미지정 |
| `--option` | 기타 조건: 주차가능, 반려동물가능, 대출가능, 엘리베이터, 옥탑, 복층. 반복하거나 쉼표로 구분 | 미지정 |
| `--move-in-now` | 즉시 입주 가능한 매물만 | 꺼짐 |
| `--household-min` | 단지 세대수 하한 (-t 아파트 만 줄 때) 범위: 0~제한 없음. | 미지정 |
| `--household-max` | 단지 세대수 상한 (-t 아파트 만 줄 때) 범위: 0~제한 없음. | 미지정 |
| `--parking-min` | 세대당 주차대수 하한 (-t 아파트 만 줄 때) 범위: 0~제한 없음. | 미지정 |
| `--limit` | 조회할 매물 수 (제외 전) 범위: 1~120. | 20 |
| `--details` | 매물마다 상세를 1회씩 더 받아 목록에 없는 관리비·등록일·번지 주소·사용승인일·방 구조를 채운다. 요청이 매물 수만큼 늘어난다 (앞 30건) | 꺼짐 |

**사용 예시**

```bash
jibsa daangn search listings 역삼동 --city 강남구 -t 원룸 --trade 월세 --deposit-max 1000 --rent-max 70
```

**반환값**

동 검색은 `regions`, `total`(조건에 맞는 매물 수를 받지 못하면 `null`이고 이유를 `notes`로 알린다), `fetched`, `returned`, `listings`(매물마다 `in_regions`: 조회한 동 안이면 `true`, 당근이 섞어 준 주변 동이면 `false`, 동을 모르면 `null`); 반경 검색은 `region`(검색 중심의 동. 받지 못하면 `null`이고 이유를 `notes`로 알린다), `radius_km`, `total`, `returned`, `listings`; 역 주변 검색은 `station`(이름·노선), `returned`, `has_more`, `listings`(매물마다 `walk_minutes`)다.

**오류와 대응**

좌표·반경 검색에 `--city`·`--expand`, 원룸 없는 `--structure`, 아파트 전용 조건의 잘못된 유형 조합은 `INVALID_ARGUMENT`. 지역 미발견은 `REGION_NOT_FOUND`이다. `--expand` 는 동 이름에만, `--city` 는 동·역 이름에만 쓴다. 다른 이름과 함께 주거나 `--city` 에 맞는 역이 없으면 `REGION_NOT_FOUND` 이고, 힌트에 옵션을 빼라는 안내나 같은 이름 역이 있는 곳이 나온다. 같은 이름의 동이 여러 곳이면(신사동 → 강남구·은평구) `REGION_AMBIGUOUS` 로 후보를 알리니 `--city` 로 좁힌다 (예: `신사동 --city 강남구`). 당근 지역 검색은 행정동도 같은 이름 후보로 주지만(역삼동 → 용인시 처인구 역삼동) 매물 지도가 있는 법정동만 세어 역삼동은 강남구 한 곳으로 찾는다 (후보마다 지도 요청 1회). 미지원 지역은 `REGION_NOT_SUPPORTED`. 목록 옵션에 없는 값이 이 명령의 다른 옵션이나 다른 소스 표현이면(`--option 반려동물`) 에러 `hint` 가 맞는 옵션(`--option 반려동물가능`)을 알려 준다. 행정동(`역삼1동`)은 당근 지역 검색에는 나오지만 매물 지도는 법정동만 있어 `REGION_NOT_FOUND` 이고, 힌트에 법정동 이름(`역삼동`)을 알려 준다. 장소 이름의 주소가 여러 시·군·구에 맞으면 `REGION_AMBIGUOUS`이며 `candidates`를 보고 시·구를 붙여 다시 검색한다. 해시 거절 시 동 검색은 지원 조건만 대체 조회하고, 지원하지 않는 조건이나 반경 검색은 `UPSTREAM_ERROR`다.

**주의사항**

동 이름만 주면 최근 매물을 최근 게시 순으로 조회한다. 실제 받은 원본 매물 수가 `--limit`에 도달하면 멈춘다. 주변 동을 확장해도 전체 조회 예산을 공유한다. 앞 동에서 예산을 다 쓰면 남은 주변 동은 조회하지 않고, `regions`에서 빼고 그 이름을 `notes`로 알린다. 첫 동에서 다 쓰면 주변 동을 고르는 요청도 하지 않아 피드에 섞여 온 주변 동 이름만 알린다 (기본 `--limit 20` 은 첫 동 20건으로 다 쓰므로 `--expand` 를 쓸 때는 `--limit` 을 늘린다). `--city`는 같은 동 이름을 구분하고, `--expand`는 주변 동을 추가한다. 같은 이름의 동이 여러 곳이면 고르지 않고 `REGION_AMBIGUOUS` 로 멈춘다. `○가` 로 나뉜 동(성수동 → 성수동1가·2가)은 모두 찾고 `--limit` 을 동끼리 나눠 쓴다 (지도 첫 페이지 20건도 몫까지만 쓴다). 주변 동 매물이 섞여 오고 `in_regions: false` 로 표시된다. `distance_km` 는 `--expand` 로 여러 동을 조회해도 처음 조회한 동의 중심에서 잰다.

동이 아닌 역 이름(예: 역삼역)은 당근 웹의 역 주변 매물 목록으로 찾는다. 매물마다 역까지 도보 분(`walk_minutes`)이 붙고 당근 목록 순서(대체로 도보 가까운 순)로 준다. 요청당 100건씩 받아 받은 수로 예산을 세며 뺀 매물은 다시 채우지 않는다. 역에서 반경으로 찾으려면 `--radius`를 준다. 이름이 같은 역이 여러 곳이면(예: 양평역은 경기 양평군·서울 영등포구) 당근 웹처럼 첫 역으로 찾고 다른 역을 `notes`로 알린다. `--city`를 주면 그 시·도·구의 역을 고른다 (역 위치의 동을 찾느라 역마다 요청 1회). 역 검색이나 역 주변 목록 조회가 실패하면(요청 제한 제외) 그 위치의 반경 검색으로 넘어가고 `notes`로 알린다.

장소 이름, 좌표 또는 명시한 `--radius`는 반경 검색이다. 기본 반경 1km, 최대 5km이며 가까운 순으로 보여 준다. 이름의 중심 위치는 당근 역·주소 검색으로 먼저 찾는다. 주소는 검색어 끝의 도로명 번호·번지까지 같거나 건물 이름이 정확히 같은 결과만 쓰고(예: 테헤란로 152, 역삼동 736-1, 강남파이낸스센터), 그런 주소가 여러 시·군·구에 있으면 고르지 않고 `REGION_AMBIGUOUS`로 후보를 알린다. 동·구 이름이나 당근이 확실히 못 찾은 이름은 직방 지역 검색으로, 직방이 요청 제한이나 서버·네트워크 오류로 실패하면 네이버로 다시 찾는다. 이때 `--city`·`--expand`는 함께 사용할 수 없다. 이름이 같은 역이 여러 곳이면 첫 역을 중심으로 쓰고 다른 역을 `notes`로 알리니, 다른 역이면 `--lat`/`--lng`로 위치를 준다. 반경 안 매물이 부족하면 반경 밖 가까운 매물도 반환할 수 있으므로 `notes`를 확인한다. 지도 번호를 가까운 순으로 고르고 정보 API에 최대 20개씩 보낸다. 보낸 ID 수로 예산을 계산하며 누락·중복·거래 불가·조건 불일치로 빠진 만큼 추가로 채우지 않는다.

`--structure`는 `-t 원룸`과 함께 쓴다. 세대수·세대당 주차 조건은 `-t 아파트`만 선택할 때 사용한다. `--with-manage-cost`는 월세 범위를 월세+관리비로 비교한다. ㎡ 조건은 일반 매물의 전용면적, 주택·건물·공장·창고의 연면적, 토지의 대지면적을 사용한다. 서로 다른 유형을 함께 검색하면 면적 기준도 섞인다.

당근에는 리 단위 지역이 없어 리를 주면 상위 읍·면 전체 매물을 조회하고 `notes` 로 알린다 (예: 양근리 → 양평읍). 같은 이름의 리가 여러 곳이면 첫 곳으로 조회하고 다른 곳을 알려 주니 `--city` 로 좁힌다. 리 이름이 역 이름과 겹치기도 해서(가오리 → 부안군 상서면, 오리 → 경기 광주시 퇴촌면) 역 주변을 찾으려면 `가오리역` 처럼 '역'을 붙인다. 당근 목록(`search listings`)은 원래 번지·등록일·관리비·방 수를 주지 않아 `address` 가 동까지, `registered_at`·`manage_cost_manwon` 이 `null` 이다. `-t 투룸` 은 당근 카테고리대로 투룸 이상이라 목록의 `room_type` 이 `null` 이다. 목록의 원룸 `room_type`(오픈형·분리형)은 당근 원룸 구조라 방이 2개인 매물에도 붙을 수 있다. 상세(`listing`)에서는 번지까지 있는 지번 주소와 등록일, 관리비, 그리고 유형과 상관없이 방 수로 정한 `room_type`(방 2개 투룸, 3개 쓰리룸, 4개 이상 포룸이상)이 나온다. 방 1개는 원룸만 오픈형·분리형이고, 오피스텔·아파트 등은 구조를 몰라 `null`이며 `room_count`로 방 수를 확인한다.

`-t 원룸`은 당근의 원룸 카테고리(오픈형·분리형)를 찾는다. 당근 매물 종류는 작성자가 고른 하나라서, 같은 오피스텔 건물의 방 1개짜리도 원룸 또는 오피스텔로 갈린다. 아파트·오피스텔·주택으로 등록된 방 1개짜리 매물까지 찾는 조건이 아니고, 원룸으로 등록했어도 방이 2개인 매물이 있다. 빌라 원룸도 작성자가 원룸 카테고리로 등록한 경우에 포함되며 건축물의 법적 용도를 보장하지 않는다. 오피스텔 원룸을 빠짐없이 보려면 `-t 원룸,오피스텔`로 함께 찾는다. 모든 건물 유형의 방 1개짜리 집이 필요하면 해당 유형도 검색하고 `listing`의 `room_count`를 확인한다. `null`이면 방 수를 알 수 없다. 당근 웹처럼 `--room-count`는 2개·3개·4개 이상만 지원한다. `--structure`를 주면 당근은 거의 원룸만 돌려주므로 함께 준 다른 유형은 대부분 빠지고 `notes`로 알린다. 당근이 원룸 조건으로 돌려준 매물은 다른 유형으로 표시돼도 빼지 않으므로 결과의 `property_type`으로 확인한다. 원룸·투룸으로 등록됐지만 오피스텔·아파트 단지에 있는 매물은 빼지 않고 매물 ID·단지 이름·건물 종류를 `notes`로 알린다. `property_type`은 작성자가 고른 종류다.

금액·면적·세대수의 하한이 상한보다 크거나 유한하지 않은 숫자이면 조회 전에 `INVALID_ARGUMENT`로 거절한다. 금액을 모르는 매물은 금액 조건을 확인할 수 없어 제외한다. 관리비 포함 월세는 서버에서 거르며 목록의 관리비는 `null`이다. 복수 거래 조건에서는 총액 상한보다 비싼 월세를 표시하지 않도록 월세 자체의 상한도 확인한다. 상세에서 관리비를 확인한다. 당근이 조건에 맞다고 준 매물이라도 목록의 거래 조건 중 검색한 거래 유형·금액에 맞는 것을 확인할 수 없으면 임의의 가격을 보여 주지 않고 빼며, 뺀 수와 사유를 `notes`로 알린다.

## 3. `listing` — 매물 하나 상세

검색한 매물의 현재 거래 조건과 구조화된 상세 정보를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `ITEM_ID` | 당근 매물 ID (search listings 결과의 id) 범위: 1~제한 없음. | 필수 |
| `--trade` | 보여 줄 거래 조건: 매매, 전세, 월세, 단기임대. search listings 결과의 trade_type 을 넘기면 목록과 같은 가격이 나온다. 기본은 대표 조건 | 미지정 |

**사용 예시**

```bash
jibsa daangn listing 100001 --trade 월세
```

**반환값**

공통 상세 필드와 당근 전용 필드(`other_trades`, 관리비 항목, 중개보수, 관심 수, 해당 유형의 단지·권리금 정보)를 준다.

**오류와 대응**

거래 완료·숨김·삭제·노출 제한·거래 조건 없음 또는 요청한 거래 조건 미제공은 `LISTING_UNAVAILABLE`.

**주의사항**

검색 결과의 `id`를 넣는다. 여러 거래 조건이 있는 매물은 검색 결과의 `trade_type`을 `--trade`로 넘기면 같은 거래 조건의 가격을 볼 수 있다. 단지 매물은 `complex_id`로 단지 정보를 이어 조회할 수 있다.


**반환값**

`region`, `trade_type`, `sort`, `returned`, `has_more`, `complexes[]`를 준다. 단지 카드는 현재 매물 수와 최근 실거래 요약을 포함한다.

**오류와 대응**

거래 유형과 가격 옵션이 충돌하거나 한도를 넘으면 `INVALID_ARGUMENT`. 지역 미발견은 `REGION_NOT_FOUND`. 같은 이름의 동·구가 여러 곳이면 `REGION_AMBIGUOUS` 로 후보를 알리니 `--city` 로 좁힌다. 구가 있는 시 이름(수원시)만 주면 시 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 구 후보(`candidates`, 예: `수원시 장안구`)를 알리니 그중 하나로 다시 찾는다. 구가 없는 세종(`세종`·`세종시`)도 시 전체로는 조회할 수 없어 `REGION_AMBIGUOUS` 로 세종의 동 후보를 알린다.

**주의사항**

현재 매물 목록이 아닌 단지 목록이다. 가격 조건과 가격 정렬은 단지의 과거 실거래 기준이다. 해당 가격의 현재 매물이 있는지는 `search listings --complex`로 확인한다. `--type`을 생략하면 도시형생활주택도 섞일 수 있다. 입주일 정렬은 사용승인일과 순서가 다를 수 있어 `notes`를 확인한다. `listing_counts`는 현재 거래 유형별 매물 수, `recent_trades`는 선택 거래 유형의 최근 실거래 요약이다.

서버에는 최대 50개씩 요청하고 응답의 커서로 다음 페이지를 이어 받는다. 1200개 조회 후에도 다음 페이지가 있으면 최대값 및 필터 안내를 제공한다. `--limit 1201`은 입력 오류다.

## 5. `complex` — 단지 하나 정보

단지의 평형·건물·학교·역 정보를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 단지 ID (위치 검색·단지 목록·매물 상세에서 받은 값). 범위: 1 이상. | 필수 |

**사용 예시**

```bash
jibsa daangn complex 100001
```

**반환값**

단지 ID·이름·주소·유형, 세대수·층수·주차·사용승인일·난방·시공사, `pyeongs`, `nearby_subways`, `schools`, `listing_count`, `review_count`, `url`을 준다. 단지 공공 정보가 없으면 `pyeongs`·`nearby_subways`·`schools` 는 `null`(모름)이다.

**오류와 대응**

존재하지 않는 단지 ID는 `NOT_FOUND`. SSR 스토어를 읽을 수 없으면 `PARSE_ERROR`.

**주의사항**

단지 이름 대신 `search locations`·`search complexes`·`school` 또는 매물 상세의 `complex_id`를 사용한다. 평형·세대수·학교·역·현재 매물 수·후기 수 등을 제공한다. `pyeongs[].area_group`은 `real-price`와 `price-trend`의 `--area`에 넣는 전용면적 묶음이다. 요청은 단지 페이지 1회(약 2MB)다.

고른 단지 하나의 현재 매물을 찾는다.

| 인자·옵션 | 설명·허용값 | 기본값 |

| `--type / -t` | 아파트, 오피스텔, 원룸, 투룸, 주택, 상가, 사무실, 건물, 토지, 공장·창고. 반복하거나 쉼표로 구분. 기본 전체. 투룸은 투룸 이상 (쓰리룸·포룸 포함) | 미지정 |

```bash

```

**반환값**

`complex_id`, `returned`, `has_more`, `listings`, 단지 `url`을 준다. 검색 거리 필드는 없다.

**오류와 대응**

지역·좌표·반경·주변 동·세대수·주차대수 옵션과 함께 주면 `INVALID_ARGUMENT`. 없는 단지는 `NOT_FOUND`.

**주의사항**

`search listings --complex <단지 ID>`는 2절 매물 검색의 단지 모드다. 단지 하나의 현재 매물을 당근 단지 화면의 매물 탭 순서로 조회한다. 지역 검색이 아니므로 중심 좌표·반경·거리 정렬·`distance_km`가 없고, 지역·좌표·반경·주변 동·세대수·주차대수 옵션은 쓸 수 없다.

조건 옵션은 `search listings` 와 같고 당근 서버에서 건다. 거래 완료·숨김 매물은 빼고, 여러 거래 조건을 올린 매물은 조건에 맞는 거래의 가격을 보여 준다. 단지 안 상가 매물도 함께 오니 필요하면 `-t 아파트` 로 좁힌다.

유형·방 구조·면적의 의미와 원룸 검색의 누락 가능성은 [검색 조건 주의사항](#2-search-listings--현재-매물-찾기)을 따른다.

## 7. `real-price` — 단지·건물 실거래가

단지 또는 매물이 속한 건물의 실거래를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 단지 ID (search locations <단지 이름> 의 complexes, 아파트·오피스텔 listing 의 complex_id). --item 을 주면 생략 범위: 1~제한 없음. | 미지정 |
| `--item` | 매물 ID. 단지 대신 그 매물이 있는 건물의 비슷한 면적 실거래를 본다 범위: 1~제한 없음. | 미지정 |
| `--trade` | 매매, 전세, 월세 중 하나 | 매매 |
| `--area` | 전용면적 묶음 (complex 결과의 pyeongs[].area_group, 예: 84). 단지로 볼 때만. 기본 전체 평형 범위: 1~제한 없음. | 미지정 |
| `--limit` | 최대 거래 수 범위: 1~1200. | 120 |

**사용 예시**

```bash
jibsa daangn real-price 100001 --trade 전세 --area 84 --limit 10
```

**반환값**

`trade_type`, `returned`, `has_more`, `transactions`, `url`; 단지 모드는 `complex_id`, `area_group`, 건물 모드는 `listing_id`를 준다.

**오류와 대응**

단지와 `--item` 동시 지정, 둘 다 누락, `--item`에 `--area` 지정은 `INVALID_ARGUMENT`. 없는 단지는 `NOT_FOUND`, 사용 불가 매물은 `LISTING_UNAVAILABLE`.

**주의사항**

단지는 `COMPLEX_ID`, 단지가 없는 매물의 건물은 `--item`을 사용하며 둘을 함께 지정할 수 없다. `--area`는 단지 조회에서만 사용한다. 단지의 전체 평형을 보려면 생략한다.

```bash
jibsa daangn real-price --item 100002 --trade 월세
```

최근 계약 순이다. 전세·월세는 최근 전월세 1200건 안에서 선택한 유형을 골라 결과가 부족할 수 있다. `--item`의 빈 결과는 그 건물의 거래가 없다는 확정이 아니라 당근이 해당 건물 실거래를 제공하지 않는 경우도 있다. `cancelled: true`는 해제된 거래로 시세·평균 계산에서 제외한다.

기본 120건·최대 1200건이다. 서버에 50건씩 요청하며 커서로 최대 24페이지를 조회한다. 추가 거래가 남으면 `has_more: true`다. `--limit`에서 멈췄으면 `notes`에서 `--limit`을 늘리라고 안내하고, 24페이지까지 보고도 남았을 때만 당근 사이트 확인을 안내한다.

## 8. `region-real-price` — 동·구 실거래가·신고가

동·구의 최근 공개 실거래나 신고가 거래를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `REGION` | 동 이름(예: '역삼동') 또는 구 이름(예: '강남구', '수원시 장안구') | 필수 |
| `--city` | 같은 이름이 여러 곳일 때 시/도나 구로 좁힘 (예: '서울', '대구광역시'. 시·도는 '서울시'·'강원도' 같은 줄임말도 된다) | 미지정 |
| `--trade` | 매매, 전세, 월세 중 하나 | 매매 |
| `--new-high` | 이전 최고가를 넘은 신고가 매매만 (가격 높은 순) | 꺼짐 |
| `--sort` | 최신 (최근 공개 순) 또는 가격 (가격 높은 순, 매매만) | 최신 |
| `--limit` | 최대 거래 수 범위: 1~1200. | 120 |

**사용 예시**

```bash
jibsa daangn region-real-price 강남구 --city 서울 --new-high
```

**반환값**

`region`, `trade_type`, `new_high`, `sort`, `returned`, `has_more`, `transactions`를 준다. 각 거래의 계약일과 공개일을 구분한다.

**오류와 대응**

전세·월세에 `--new-high` 또는 가격 정렬을 지정하면 `INVALID_ARGUMENT`. 지역 미발견은 `REGION_NOT_FOUND`. 구가 있는 시 이름(수원시)만 주면 시 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 구 후보(`candidates`, 예: `수원시 장안구`)를 알리니 그중 하나로 다시 찾는다.

**주의사항**

아파트 단지 외에 빌라·오피스텔 같은 소규모 건물 거래도 섞인다. 이름이 동과 같으면 그 동, 아니면 같은 이름의 구를 본다. 구가 없는 세종(`세종`·`세종시`)은 세종특별자치시 전체 거래를 주고 `notes` 로 알린다. 리 거래 주소는 당근이 읍·면을 빼고 주는데(`경기 양평군 공흥리`), 읍·면으로 조회했으면 그 읍·면을 넣어 준다(`경기도 양평군 양평읍 공흥리`). 군·세종 전체로 조회한 리 거래는 읍·면을 알 수 없어 빠진 채로 나온다. 같은 이름의 동·구가 여러 곳이면 고르지 않고 `REGION_AMBIGUOUS` 로 후보를 알리니 `--city` 로 좁힌다 (구는 시·도로 좁힌다: `중구 --city 서울`).

기본 최신 정렬은 계약일이 아니라 최근 공개 순이다. `--sort 가격`(가격 높은 순)과 `--new-high`(이전 최고가를 넘은 신고가 매매만, 가격 높은 순)는 매매만 지원한다. `--new-high` 는 가장 최근 공개일만이 아니라 이전 공개일의 신고가까지 받는다 (당근 웹은 최근 공개일만 보여 줘 그날 신고가가 없으면 비어 있다). 당근이 주는 신고가는 최근 몇 달 치라 많지 않다 (2026-10-11 실측: 강남구 20건, 역삼동 3건). 전세·월세는 당근이 섞어 주므로 최근 전월세 1200건 안에서 선택 유형을 고른다.

기본 120건·최대 1200건이다. 50건씩 커서로 최대 24페이지를 조회한다. 추가 거래가 남으면 `has_more: true`이고, `--limit`에서 멈췄으면 `--limit`을 늘리라고, 24페이지까지 보고도 남았을 때만 당근 사이트 확인을 안내한다.

## 9. `price-trend` — 월별 가격 추이

단지의 월별 평균 실거래가와 기간 변화율을 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 단지 ID (complexes·school·search locations <단지 이름> 결과, 아파트·오피스텔 listing 의 complex_id) 범위: 1~제한 없음. | 필수 |
| `--area` | 전용면적 묶음 (complex 결과의 pyeongs[].area_group, 예: 84). 기본 전 평형을 섞은 평균 범위: 1~제한 없음. | 미지정 |
| `--trade` | 매매, 전세 중 하나 (월세 시세 그래프는 없다) | 매매 |
| `--years` | 보여 줄 기간이자 변화율을 비교할 햇수 범위: 1~15. | 3 |

**사용 예시**

```bash
jibsa daangn price-trend 100001 --area 84 --trade 매매 --years 3
```

**반환값**

`complex_id`, `trade_type`, `area_group`, `years`, `total_transactions`, `summary`, `points`, `url`을 준다. `points`는 거래가 있는 달만 포함한다.

**오류와 대응**

월세 또는 기간 범위 밖 입력은 `INVALID_ARGUMENT`. 없는 단지는 `NOT_FOUND`. 비교 구간 거래 부족은 오류 대신 `notes`·`null`로 알린다.

**주의사항**

월별 평균 실거래가와 선택 기간 전 대비 변화율을 제공한다. 매매·전세만 지원하며 월세 그래프는 없다. `--area`를 생략하면 모든 평형을 섞은 평균이다. `--years`는 표시 기간과 변화율 비교 기간을 함께 정한다. `points`는 거래가 있는 달만 오래된 순이며 `transaction_count`로 표본 수를 확인한다. 비교 거래 수 부족·오래된 거래 안내는 `notes`를 확인한다.

변화율은 마지막 거래 달까지 최근 3개월과 `--years`년 전 3개월의 거래 수 가중 평균을 비교한다. 비교 구간 거래가 없으면 `summary`는 `null`이다. 구간 거래가 3건 미만이거나 마지막 거래가 6개월 넘게 지났으면 `notes`로 알린다.

**오류와 대응**

학교를 찾지 못하면 `NOT_FOUND`. 중·고등학교 배정 단지 없음은 정상 빈 목록과 `notes`다.

**주의사항**

학교 이름 일부로도 검색한다. 같은 이름이 여러 곳에 대응하면 이름이 같은 첫 후보를 쓰고 다른 후보를 `notes`로 안내하니, 주소를 확인하거나 `--city`로 좁힌다. 배정 단지는 초등학교만 제공하고 중·고등학교는 학교 정보만 제공한다. 단지는 세대수 많은 순이며 소규모 빌라형 단지도 섞일 수 있다. 단지 유형과 세대수 조건은 받은 결과에서 적용한다. 배정 단지 카드의 `recent_trades`는 매매다. 학교 전화·좌표는 출력하지 않는다.

배정 단지는 기본 120곳·최대 1200곳을 표시한다. 일부만 표시하면 전체 개수와 표시 개수를 알리고, 최대값에서는 유형·세대수 조건으로 좁히도록 안내한다.

| 인자·옵션 | 설명·허용값 | 기본값 |

```bash

```

**반환값**

`workplace_station`, `max_minutes`, `reachable_stations`(회사 역 포함), `searched_stations`, `listings`, 역별 `stations[]`, `returned`, `unique_returned`를 준다. 매물은 지하철·도보·환승·예상 통근 시간을 포함한다.

**오류와 대응**

이름·좌표 누락 또는 지원하지 않는 조건 조합은 `INVALID_ARGUMENT`. 위치·인근 역 미발견 및 쿼리 거절은 에러의 힌트를 확인한다. 회사 위치 이름 처리는 `search listings` 와 같다 (주소가 여러 곳이면 `REGION_AMBIGUOUS`). 직방·네이버 위치 해석도 요청 제한에 걸릴 수 있다.

**주의사항**

회사에서 가까운 역을 찾고 그 역까지 지하철로 갈 수 있는 역 주변의 매물을 예상 통근 시간 짧은 순으로 보여 준다. `--max-minutes`는 총 통근 시간이 아니라 역 사이 지하철 시간의 상한이다. 당근은 지하철 60분 안 역까지만 주어 60을 넘게 주면 60분까지의 역만 찾고 `notes`로 알린다. 갈 수 있는 역 목록은 200곳까지만 받아 `reachable_stations`는 그 안에서 센 수이고, 더 있으면 `notes`로 알린다. 가까운 역부터 최대 10곳을 조회하며 `--limit`은 전체가 아닌 역당 개수다. 기본 20건·최대 120건을 받은 수로 세어 100건씩 다음 페이지를 이어 받고, 같은 역 안의 중복·거래 불가·조건 불일치는 제외해도 추가로 채우지 않는다. 여러 역에 걸친 같은 매물은 각 역에 유지한다. 결과는 `stations[]`로 묶이며 역마다 통근 시간이 짧은 순으로 정렬한다. `returned`는 역별 합계, `unique_returned`는 전체 서로 다른 매물 수다. `commute_minutes`는 도보+지하철+회사까지 도보이며 대기 시간은 포함하지 않는다. 매물→역 또는 회사 역→회사 도보 시간을 모르면 `commute_minutes`는 `null`이다. 지하철 시간을 모르는 역은 시간 상한을 확인할 수 없어 제외하고 안내한다. 환승 횟수를 모르면 `transfers`는 `null`이다.

위치 이름은 직방으로 해석하고 직방 요청 제한 시 네이버로 다시 찾는다. 매물의 `distance_km`는 회사까지 직선거리다. [통근 매물 필드](#통근-매물-search-commute)를 함께 확인한다.

유형·방 구조·면적의 의미와 원룸 검색의 누락 가능성은 [검색 조건 주의사항](#2-search-listings--현재-매물-찾기)을 따른다.

## 12. `region-reviews` — 지역 후기 수·후기 많은 단지

동네의 후기 유무·수와 후기 많은 단지를 확인한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `REGION` | 동 이름(예: '역삼동') 또는 구 이름(예: '강남구', '수원시 장안구') | 필수 |
| `--city` | 같은 이름이 여러 곳일 때 시/도나 구로 좁힘 (예: '서울', '대구광역시'. 시·도는 '서울시'·'강원도' 같은 줄임말도 된다) | 미지정 |
| `--top` | 후기 많은 단지 수 범위: 1~20. | 10 |

**사용 예시**

```bash
jibsa daangn region-reviews 역삼동 --city 강남구 --top 10
```

**반환값**

`region`, `has_reviews`, `review_count`, `top_complexes`, `url`을 준다. 후기 본문과 요약은 없다.

**오류와 대응**

지역 미발견은 `REGION_NOT_FOUND`. 같은 이름의 동·구가 여러 곳이면 `REGION_AMBIGUOUS` 로 후보를 알리니 `--city` 로 좁힌다. 구가 있는 시 이름(수원시)만 주면 시 전체는 조회할 수 없어 `REGION_AMBIGUOUS` 로 구 후보(`candidates`, 예: `수원시 장안구`)를 알리니 그중 하나로 다시 찾는다. 구가 없는 세종(`세종`·`세종시`)도 시 전체로는 조회할 수 없어 `REGION_AMBIGUOUS` 로 세종의 동 후보를 알린다. 구가 없는 지역은 가능한 조회 범위를 `notes`로 안내한다.

**주의사항**

후기 본문과 당근이 만든 동네 요약 글은 내보내지 않고, 내용은 `url`(당근 구의 동네 후기 페이지, 구가 없는 시는 동 지도 페이지)에서 보라고 `notes` 로 알린다. `top_complexes` 는 그 구에서 후기가 많은 단지(`complex_id`, 이름, 유형, 후기 수)다.

`review_count` 는 동만 있다. 당근 동네 요약이 후기를 60개까지만 세어 `60` 이면 60개 이상이다 (`notes` 로 알린다). 구는 당근이 수를 주지 않아 `null` 이다. 동도 동네 요약을 받지 못하면 `null` 이고 이유를 `notes` 로 알린다 (후기가 있는지는 후기 목록으로 다시 본다). 지역 고르는 방식(`--city`)은 [`region-real-price`](#8-region-real-price--동구-실거래가신고가)와 같다.

## 15. `compare` — 단지 나란히 비교

단지 여러 곳(최대 5)을 같은 항목으로 비교한다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_IDS` | 단지 ID 여러 개 (최대 5개) | 필수 |

**사용 예시**

```bash
jibsa daangn compare 10697092 10699673 10697091
```

**반환값**

`returned`, `complexes[]`. 단지마다 이름·유형·주소, 사용승인일, 동·세대수, 세대당 주차, 최저·최고 층, 현재 매물 수, `asking`(현재 호가 매매·전세·월세 범위), ㎡당 관리비(`manage_cost_per_m2_manwon`, K-apt 최근 달), 후기 수, 배정 학교(거리·도보), 주변 역(거리·도보), `area_groups[]`(전용면적 묶음별 KB 시세 하위·일반·상위, 최근 매매·전월세 실거래), `url`. 단지 공공 정보가 없으면 배정 학교·주변 역·`area_groups` 는 `null`(모름)이다.

**오류와 대응**

단지가 5개를 넘으면 `INVALID_ARGUMENT`, 없는 단지는 `NOT_FOUND`.

**주의사항**

단지마다 요청 1회다. `asking` 은 당근에 올라온 아파트 매물 앞 30건의 호가라 실제 거래가는 `area_groups` 의 실거래를 본다. 월세 0은 전세로 센다. 단기임대는 당근이 금액을 주지 않아 세지 않는다. 후기 요약 글은 주지 않는다 (후기 수만). `area_groups[].area_group` 은 `real-price`·`price-trend` 의 `--area` 에 넣는다.

## 16. `nearby-complexes` — 같은 동 단지

기준 단지와 같은 동의 다른 단지를 세대수 많은 순으로 본다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `COMPLEX_ID` | 기준 단지 ID | 필수 |
| `--limit` | 최대 단지 수 범위: 1~1200. | 50 |

**사용 예시**

```bash
jibsa daangn nearby-complexes 10697092 --limit 20
```

**반환값**

`complex_id`, `region`(동), `total`, `returned`, `complexes[]`(`complex_id`, `name`, `type`, `households`, `listing_count`).

**오류와 대응**

없는 단지는 `NOT_FOUND`, 단지의 동을 찾지 못하면 `REGION_NOT_FOUND`.

**주의사항**

요청 4회다 (단지 → 동 → 동의 단지 → 단지 카드). 같은 동 단지는 1200곳까지 한 번에 받고, 1200곳을 채우면 더 있을 수 있다고 `notes` 로 알린다. 가격 조건으로 단지를 고르려면 `search complexes` 를 쓴다.

## 17. `good-neighborhoods` — 살기 좋은 동 추천

당근 웹의 좋은 동네 추천처럼 라이프스타일 지표로 동 순위를 본다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `--lifestyle` | 직장인자취, 대학생자취, 부부, 아이와함께, 반려동물과함께, 은퇴후 중 하나 | 필수 |
| `--region` | 시·도(예: 서울) 또는 시·군·구(예: 강남구, '서울 중구'). 시·도는 '서울시'·'충북' 같은 줄임말도 되고, 전남광주통합특별시(전남)는 광주·전남을 함께 찾고, 옛 이름(광주·광주광역시·전라남도)은 그 한 곳만 찾는다. 구가 있는 시는 '분당구'·'성남시 분당구' 로 한 구를, '수원시' 로 그 시의 구 모두를 찾는다. 반복하거나 쉼표로 구분 | 전국 |
| `--limit` | 최대 동 수 범위: 1~50. | 10 |

**사용 예시**

```bash
jibsa daangn good-neighborhoods --lifestyle 직장인자취 --region 서울
```

**반환값**

`lifestyle`, `indicators`(쓴 지표 3개), `regions`, `returned`, `neighborhoods[]`(`rank`, `sigungu`, `dong`, `region_id`, `description` 한 줄 설명).

**오류와 대응**

`--lifestyle` 이 비었거나 둘 이상이면 `INVALID_ARGUMENT`. 여러 시·도에 있는 시·군·구 이름(중구·서구 등)만 주면 `REGION_AMBIGUOUS` 로 후보(`candidates`)를 알려 준다. 시·도를 앞에 붙인다 (예: `--region '서울특별시 중구'`). 없는 지역은 `REGION_NOT_FOUND`.

**주의사항**

지표는 당근 웹의 라이프스타일 카드와 같다 (예: 직장인자취 = 1인 가구 많은·교통 편리한·외식하기 좋은). `dong` 은 행정동(예: 역삼1동)이라, 매물은 법정동 이름(역삼동)으로 `search listings` 에서 찾는다. 동네 후기 요약 글은 주지 않는다.

## 18. `trending-complexes` — 요즘 많이 보는 단지

동 주변에서 요즘 당근 사용자가 많이 보는 단지 순위를 본다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `DONG` | 동 이름 (예: 역삼동) | 필수 |
| `--city` | 동명이 여러 곳일 때 시/도나 구로 좁힘 (시·도는 '서울시'·'강원도' 같은 줄임말도 된다) | 미지정 |

**사용 예시**

```bash
jibsa daangn trending-complexes 역삼동 --city 강남구
```

**반환값**

`region`, `returned`, `complexes[]`(`rank`, `complex_id`, `name`, `type`, `address`, `households`, `approved_at`, 대표 평형 전용면적, 대표 평형 최근 매매가).

**주의사항**

당근이 동 주변 단지를 9곳쯤만 주어 `--limit` 이 없다. 사진은 주지 않는다. 인기 단지를 주지 않는 동(자곡동, 세종의 동 등)은 `returned: 0` 이고 `notes` 로 `search complexes` 를 쓰라고 알린다. 단지가 없다는 뜻은 아니다. 지역 미발견은 `REGION_NOT_FOUND`. 같은 이름의 동이 여러 곳이면 고르지 않고 `REGION_AMBIGUOUS` 로 후보를 알리니 `--city` 로 좁힌다.

## 19. `popular-listings` — 조회수 많은 매물

동이 속한 구에서 조회수 순위가 높은 현재 매물을 본다.

| 인자·옵션 | 설명·허용값 | 기본값 |
| --- | --- | --- |
| `DONG` | 동 이름 (예: 역삼동). 순위는 그 동이 속한 구 전체다 (구가 없는 세종은 그 동 안) | 필수 |
| `--city` | 동명이 여러 곳일 때 시/도나 구로 좁힘 (시·도는 '서울시'·'강원도' 같은 줄임말도 된다) | 미지정 |
| `--type` / `-t` | 매물 종류 (`search listings` 와 같다) | 전체 |
| `--limit` | 조회할 매물 수 (제외 전) 범위: 1~100. | 20 |

**사용 예시**

```bash
jibsa daangn popular-listings 역삼동 -t 원룸
```

**반환값**

`region`, `returned`, `listings[]`(공통 매물 필드 + 조회수 순위 `rank`).

**주의사항**

순위가 매겨진 매물은 구마다 100건쯤이다. 구가 없는 세종은 그 동 안에서만 순위를 매겨(2026-10-11 실측: 새롬동 7건·반곡동 1건) 결과가 적고, `notes` 가 그 동 기준이라고 알린다. 받은 수로 예산을 세고 거래 불가로 뺀 매물은 다시 채우지 않으며, 뺀 매물의 순위 자리는 비운다. 매물 좌표가 없어 `distance_km` 는 없다. 같은 이름의 동이 여러 곳이면 고르지 않고 `REGION_AMBIGUOUS` 로 후보를 알리니 `--city` 로 좁힌다.

## 기본값과 조회 한도

| 명령 | CLI 기본 / 최대 |
| --- | --- |
| `search listings`, `search listings --complex` | 20 / 120건 |
| `search commute` | 역당 20 / 120건 (최대 10역, 역마다 100건씩 페이지를 넘긴다) |
| `search complexes` | 120 / 1200단지 |
| `real-price`, `region-real-price` | 120 / 1200건 |
| `school` | 120 / 1200단지 |
| `nearby-complexes` | 50 / 1200단지 |
| `region-reviews --top` | 10 / 20단지 |
| `price-trend --years` | 3 / 15년 |
| `search locations` | 120 / 1200단지 후보 (지역 후보는 제한하지 않음) |
| 역 주변 `search listings` | 20 / 120건 (요청당 100건) |
| `developments` | 50 / 300사업 (반경 최대 5km) |
| `preschools` | 30 / 200곳 (반경 최대 3km) |
| `compare` | 단지 최대 5곳 |
| `good-neighborhoods` | 10 / 50동 |
| `popular-listings` | 20 / 100건 |
| `listing`, `complex`, `development`, `preschool`, `trending-complexes` | `--limit` 없음 |

여기의 최대값은 CLI 정책이다. 서버가 요청 한 번에 반환할 수 있는 최대 개수와 같다는 뜻은 아니다. 검색 경로마다 페이지·후처리·조회 범위가 달라 결과가 요청한 개수보다 적을 수 있다. 동·단지 매물은 요청당 20건씩 최대 6페이지를 조회한다.

당근 목록 응답을 조회 한도 때문에 잘라내면 `notes`에 실제 조회된 개수와 표시 개수를 따로 안내한다. 예: “조회된 어린이집·유치원 205곳 중 --limit 200 에 맞춰 200곳만 보여드립니다. -t·--radius 로 좁히세요.” 서버의 다음 페이지 표시가 없어도 초과 결과를 잘랐다면 안내하며, 중복·거래 불가·조건 불일치 제외 안내와 구분한다. 단지 후보·지역 단지·단지 매물은 남은 한도만큼만 요청해 서버가 더 주지 않으므로 이 안내 없이 `has_more`와 `--limit` 안내로만 알린다.

## 요청 제한과 도움말

요청 제한 정책과 `jibsa limits` 사용법은 [공통 사용 규칙](common.md#요청-제한과-limits)에 있다. 이름으로 위치를 찾는 명령은 직방(막히거나 실패하면 네이버) 요청도 쓰므로 요청 제한 에러의 `source` 가 직방·네이버일 수 있다. 직방과 네이버 모두 위치를 찾지 못하면 에러의 `source` 가 `zigbang` 이니 당근은 그대로 쓸 수 있다 (당근 동 이름이나 `--lat/--lng` 로 다시 찾는다). 웹 쿼리가 거절되면(`UPSTREAM_ERROR`) 출력된 힌트와 업데이트 안내를 따른다. 대체 경로가 없는 명령도 같은 코드로 끝난다.

```bash
jibsa daangn --help
jibsa daangn search listings --help
jibsa daangn real-price --help
```

| 소스·조회 유형 | 필드 | 뜻 |
| --- | --- | --- |
| 당근 | `other_trades` | 보여 주는 조건 외에 함께 올라온 거래 조건 (만원, 예: `["전세 20000", "월세 1000/50"]`). 없으면 `[]`. 기본은 대표 조건을 보여 주고 `listing --trade` 로 고른다 |

| 당근 | `watch_count` | 당근에서 이 매물을 관심 목록에 넣은 사람 수 (조회수가 아니다) |

| `region` | 조회한 지역 (`name`, `region_id`, `level`: `동`·`구`) |
| `trade_date`, `published_at` | 계약일, 실거래가 공개된 날 (신고가에는 공개일이 없다) |
| `address`, `building_name`, `complex_id` | 동까지 주소, 건물·단지 이름, 당근 단지 ID (`daangn complex`·`real-price` 에 넘긴다. 당근 단지가 아니면 키가 없다) |
| `households`, `approved_at` | 건물·단지 세대수, 사용승인일 |
| `area_m2`, `floor` | 전용면적, 층 |
| `price_manwon` / `deposit_manwon`, `rent_manwon` | 매매가 / 보증금, 월세 (만원) |
| `cancelled`, `deal_type` | 해제된 거래, 중개거래·직거래 (매매만) |
| `renewal` | 갱신 계약 (전월세만). 당근이 계약 종류를 주지 않으면 `null` (지역 실거래 전월세의 2%쯤) |
| `previous_high_manwon`, `previous_high_date` | 이전 최고가와 그 계약일 (`--new-high` 만) |

### 통근 매물 (`search commute`)

| 필드 | 뜻 |
|---|---|
| `commute_station` | 타는 역 (매물 주변 역) |
| `subway_minutes`, `transfers` | 타는 역에서 회사 역까지 지하철 시간(분), 환승 횟수 |
| `walk_to_station_minutes` | 매물에서 타는 역까지 도보(분). 당근이 모르면 `null` |
| `commute_minutes` | 예상 통근 시간 = 매물→역 도보 + 지하철 + 회사 역→회사 도보. 기다리는 시간은 넣지 않는다. 도보 시간을 모르면 `null` |

### 단지·건물 실거래 (`real-price`)

| 필드 | 뜻 |
|---|---|
| `trade_date`, `area_m2`, `floor` | 계약일, 전용면적(㎡), 층 |
| `price_manwon` / `deposit_manwon`, `rent_manwon` | 매매가 / 보증금, 월세 (만원). 거래 유형에 없는 필드는 키가 없다 |
| `cancelled`, `registered` | 신고 뒤 해제된 거래, 등기까지 마친 거래 (매매만) |
| `presale` | `분양권`·`입주권` 거래 (매매만, 해당할 때만 키가 있다) |
| `renewal` | 갱신·재계약 (전월세만). 새 계약보다 낮게 잡히는 경우가 많다. 당근이 계약 종류를 주지 않으면 `null` |
| `has_more` | 더 오래된 거래가 있는지. 시세 그래프는 `url` 의 단지 페이지에서 본다 |

## 매물 해석 시 주의사항

상세의 `options`에 있는 “대출 가능”은 작성자가 전세자금대출 가능으로 표시한 것이며 융자 여부가 아니다. 실제 대출은 계약 전 은행에서 확인한다.

동 피드에는 구 경계를 넘는 주변 동이 섞일 수 있으므로 각 매물 주소를 확인한다. `--expand`가 같은 구의 다른 동으로 채워질 때 가까운 순이라고 단정하지 않는다.

비교 구간이 적거나 오래된 가격 추이는 `notes`와 거래 수를 함께 설명한다.
